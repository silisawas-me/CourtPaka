# แผน: ทำให้สนามจริงใช้ badPaka ได้ทั้งวัน โดยเริ่มจาก 4 เมนู

## Context
เจ้าของต้องการให้ระบบ "สมบูรณ์" ในความหมาย **สนามจริงเปิดร้าน รับจอง เก็บเงิน ปิดยอด ได้ครบทั้งวัน แล้วขึ้น UAT ให้สนามจริงลอง** (ตอบเมื่อ 2026-09-29)
- 4 เมนูหลัก (ตารางคอร์ท · ราคา & ช่วงพีค · รายได้ · สมาชิก) คือแกน · **"อื่น ๆ" เก็บไว้ตามเดิม ยังไม่ย้าย/ยังไม่ลบ** (คำตอบ: "เก็บไว้ก่อน ยังไม่ทำอะไร") — งานประจำวันที่อยู่ในนั้น (ตรวจสลิป, ปิดยอด, ยกเลิก/no-show/คืนเงิน, ตั้งค่า, เชิญพนักงาน) ยังใช้ผ่าน "อื่น ๆ" ได้
- **หน้าจอใหม่ = ผมวาดด้วย Design artifact บน claude.ai ก่อน** → เจ้าของดู/คอมเมนต์/อนุมัติ → ค่อยเขียนโค้ด (ตาม [[follow-the-design-literally]])
- PR #114 (mock ตาม design, ชื่อผู้จอง, login 1/1, เมนูพับ, เอาฟอร์มขายแพ็กเกจออก) CI ผ่านครบ รอ merge

ผลสำรวจ: ช่องว่างที่ทำให้ "วันจริง" ยังไม่ครบ
1. **สมาชิก:** ขายแพ็กเกจไม่ได้เลยจากหน้าจอ (ฟอร์มถูกเอาออก, API `POST /api/venues/{id}/packages` ยังอยู่)
2. **ตารางคอร์ท:** แผงขวายังไม่มี ยกเลิก / no-show / รับเงินบางส่วน — ต้องกดไป "การจองรายวัน" ใน "อื่น ๆ" (ยังทำได้ แค่ไม่สะดวก)
3. **เวลาผ่อนผัน** (`PUT /api/venues/{id}/grace`) ไม่มีหน้าจอตั้งเลย
4. **ขึ้นใช้จริงไม่ได้:** D17 สมัครเปิดให้ทุกคน / เจ้าของใหม่ไม่มีทางได้บัญชี, ยังไม่เลือกผู้ให้บริการอีเมล, สลิปเก็บใน volume (ยังไม่ object storage), deploy ยังไม่เคยรัน, อีเมล/LINE ถึงผู้จองลิงก์ไปหน้า `/bookings/{id}` ที่ไม่มีแล้ว
5. ไม่มีฝั่งผู้จอง → "จองผ่านแอป" เกิดขึ้นไม่ได้ในวันจริง (สนามรับจองหน้าเคาน์เตอร์/โทรศัพท์ได้ครบ)
