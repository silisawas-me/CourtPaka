# ตัดฝั่งผู้จองออกจากแอป (ชั่วคราว)

## ที่มา

2026-09-28 เจ้าของบอกว่า "ตอนนี้มั่วมาก ตัดส่วนของคน booking ไปก่อนเลย" แล้วเลือก **ลบโค้ดทิ้ง** (ไม่ใช่แค่ซ่อน)
และชี้ว่าที่มั่วคือ เมนู/บาร์บน · หน้าแรก · หน้าฝั่งสนาม · ทั้งแอป — ให้แอปโฟกัสที่เจ้าของสนาม

### เพิ่มระหว่างทาง (2026-09-28): เหลือแค่ฝั่งสนาม · สองประตู admin / พนักงาน · ไม่มีสมัครเอง

เจ้าของสั่งต่อ: "เอาแค่ฝั่งสนาม แยกเป็น login admin กับ พนักงาน" แล้วตอบคำถามว่า admin = **เจ้าของ/ผู้จัดการสนาม** ·
**สองประตู บัญชีเดิม** · **เอาการสมัครเองออก**

| # | เรื่อง | ตัดสิน |
|---|---|---|
| D12 | หน้าแรก | สองประตู: "เจ้าของ / ผู้จัดการ" → `/login?as=admin` · "พนักงาน" → `/login?as=staff` |
| D13 | ประตู admin | หลัง login ต้องเป็น **Owner อย่างน้อยหนึ่งสนาม** (หรือ platform admin) ไม่งั้น logout + บอกให้ใช้ประตูพนักงาน · ลงที่ "สนามของฉัน" (platform admin ลงที่ `/admin/venues`) |
| D14 | ประตูพนักงาน | ต้องเป็นสมาชิกอย่างน้อยหนึ่งสนาม ไม่งั้น logout + บอกให้ขอคำเชิญ · ลงที่บอร์ด "ตอนนี้" ถ้ามีสนามเดียว ไม่งั้น "สนามของฉัน" |
| D15 | การตัดสินประตูอยู่ที่หน้าจอ | **เป็นการพาไปถูกที่ ไม่ใช่การให้สิทธิ์** — ทุก endpoint ยังตรวจสิทธิ์ต่อสนามที่ server เหมือนเดิม คนที่เข้าผิดประตูไม่ได้อะไรเพิ่ม · อ่านบทบาทจาก `/api/venues/mine` (`role`) ไม่เดาเอง |
| D16 | สมัครเอง | ลบปุ่มสมัครทุกที่ ลบ LINE (ปุ่ม, หน้า `/register/line`) · **เก็บหน้า `/register` ไว้ทางเดียว: จากหน้า login ที่มาจากลิงก์คำเชิญ** ไม่งั้นพนักงานที่ถูกเชิญแต่ยังไม่มีบัญชีรับคำเชิญไม่ได้ |
| D17 | ⚠️ ยังเปิดอยู่ | (3) **อีเมล/LINE ที่ backend ส่งถึงผู้จองยังมีลิงก์ `/bookings/{id}`** ซึ่งไม่มีหน้าแล้ว (พาไปหน้าแรก) · (1) **API สมัคร (`POST /api/auth/register`) ยังเปิด** — หน้าจอไม่มีปุ่ม แต่ยิงตรงได้ · ปิดจริงต้องให้ backend รับสมัครเฉพาะที่มีคำเชิญ (2) **เจ้าของสนามใหม่ไม่มีทางได้บัญชี** นอกจากถูกเชิญ — ต้องตัดสินว่าใครสร้างให้ (platform admin?) |

**เอากลับ:** ทั้งหมดอยู่ใน git · revert PR นี้ = ได้ฝั่งผู้จองคืน (backend ไม่ได้ถูกแตะ)
