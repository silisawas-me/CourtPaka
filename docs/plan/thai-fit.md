# ให้ฝั่งสนามเหมาะกับการใช้งานในไทย (thai-fit)

เจ้าของถามว่าแบบหน้า "ปิดยอด & ตั้งค่าร้าน" (artifact `AvLZEdyqXs5WAsgV3YeAJm`) คิดถึงการใช้งานในไทยแล้วหรือยัง
คำตอบคือยังไม่ครบ ผมเสนอหกข้อ และ **เจ้าของตอบ "ทุกข้อโอเคเลย" (2026-10-03)** พร้อมสั่งเพิ่มสองเรื่อง:

- **ตรวจสลิป:** ทำหน้าจอไว้ก่อน ส่วนบริการตรวจอัตโนมัติค่อยตัดสินทีหลัง แต่จะใช้แน่นอน ให้เก็บรายละเอียดไว้ในไฟล์นี้
- **ใบเสร็จ:** ทำแบบจำลองตามกฎหมายเป็นรูปแบบของเราเองไปก่อน

ลำดับงานยังเป็น "ฝั่งสนามให้ครบก่อน แล้วค่อยทำแอปผู้จอง" (2026-10-03)

## T5 · บริการตรวจสลิปอัตโนมัติ (ยังไม่ตัดสิน · ต้องถามเจ้าของก่อนจ่ายเงิน)

**ทำงานยังไง:** สลิปของธนาคารไทยทุกใบมี mini-QR ตามมาตรฐานของธนาคารแห่งประเทศไทย ข้างในมีรหัสธนาคารผู้โอนกับเลขอ้างอิงรายการ
บริการตรวจสลิปอ่าน QR นั้นแล้วถามธนาคารว่ามีรายการนี้จริงไหม ได้ยอด เวลา ชื่อผู้โอน และบัญชีผู้รับกลับมา
จึงจับสลิปปลอม สลิปที่แก้ยอด และสลิปที่ใช้ซ้ำได้

**ตัวเลือก** (ราคาจากเว็บของผู้ให้บริการ ค้นเมื่อ 2026-10-03 ต้องเช็กอีกครั้งก่อนสมัคร):

| ผู้ให้บริการ | แบบ | ราคาเริ่มต้น | หมายเหตุ |
|---|---|---|---|
| [SlipOK](https://slipok.com/) | API + LINE bot | **ฟรี 100 สลิป/เดือน** แล้ว 0.31 บาท/สลิป | ตัวเลือกแรกถ้าเริ่มจากของฟรี |
| [EasySlip](https://easyslip.com/api-products/) | API (QR payload / รูป / base64 / URL) | 350 บาท/เดือน 1,000 ครั้ง · 700 บาท/เดือน 2,500 ครั้ง | เอกสาร API ชัด ([docs](https://document.easyslip.com/en/)) |
| [Thunder](https://thunder.in.th/slip-verification/) | API | 99 บาท 400 สลิป | มีบทความเทียบราคา ([ลิงก์](https://thunder.in.th/blog/cheapest-slip-verification-api/)) |
| [Slip2Go](https://slip2go.com/) | API + LINE OA | 88 บาท 100 สลิป | ระบบโทเคน |
| API ของธนาคารเอง (SCB / KBank Slip Verification) | API | ต้องเป็นพาร์ทเนอร์ของธนาคาร | ตรวจได้เฉพาะสลิปของธนาคารนั้น ([SCB](https://developer.scb.co.th/)) |

**สิ่งที่ต้องทำฝั่งเราไม่ว่าจะเลือกเจ้าไหน:**
- อ่าน mini-QR ที่ backend ตอนรับสลิป (มี library open source อ่านได้ เช่น [promptpay-slip-parser](https://github.com/nuttakulsv/promptpay-slip-parser), [slipverify](https://github.com/maythiwat/slipverify)) แล้วเก็บเลขอ้างอิงไว้กับ `PaymentSlip` — ทำได้ก่อนเลือกบริการ และใช้จับสลิปซ้ำได้แม่นกว่า hash ของไฟล์
- ผลตรวจเป็นแค่ **ข้อมูลประกอบให้คนกด** ไม่ใช่ตัวตัดสินแทนสนาม (คนที่ยืนยันยังเป็นสนาม เหมือน US-12) จนกว่าเจ้าของจะสั่งให้ยืนยันอัตโนมัติ
- เทียบ **บัญชีผู้รับ** กับพร้อมเพย์ของสนาม และ **ยอด** กับยอดที่ขอ
- key ของบริการเป็น secret ของ deployment (ห้าม commit) · ส่งรูปสลิปให้บุคคลที่สาม = ต้องใส่ในนโยบาย PDPA
- ทำเป็น interface (`ISlipChecker`) มีตัวปลอมสำหรับ dev/test เหมือน `LoggingLineMessenger`

## T6 · รูปแบบเอกสาร (จำลอง ตามเอกสารวิจัย `docs/research/reports/ข้อกำหนดภาษีไทยสำหรับแพลตฟอร์มจองสนาม.md`)

สามแบบ เลือกจากสถานะ VAT ของสนาม (`Venue.Business`) ไม่ใช่ให้คนเลือก:

1. **ใบเสร็จรับเงิน** — สนามที่ **ไม่จด VAT** (ม.105 ทวิ): เลขผู้เสียภาษีของสนาม · ชื่อสนาม · เลขที่ (เล่ม/ใบ) · วันที่ · จำนวนเงิน · รายการที่ราคา ≥ 100 บาท · **ห้ามมีคำว่า "ใบกำกับภาษี" และห้ามมีบรรทัด VAT** (ม.86/13)
2. **ใบกำกับภาษีอย่างย่อ** — สนามที่ **จด VAT** ขายปลีก (ม.86/6): คำว่า "ใบกำกับภาษีอย่างย่อ" เด่นชัด · ชื่อและเลขผู้เสียภาษีของสนาม · เลขที่ · รายการ · **"ราคานี้รวมภาษีมูลค่าเพิ่มแล้ว"** · วันที่
3. **ใบกำกับภาษีเต็มรูป** — สนามจด VAT และ **ลูกค้าขอ** (ม.86/4 + ประกาศฯ 199): เพิ่มที่อยู่สนาม · ชื่อ ที่อยู่ เลขผู้เสียภาษี และสำนักงานใหญ่/สาขาของผู้ซื้อ · แยกมูลค่าก่อน VAT กับ VAT 7%

ทุกแบบ: **เลขที่ออกจาก `DocumentNumbers` (ไม่ข้าม) แยกต่อสนาม** · **ไม่มีชื่อหรือเลขผู้เสียภาษีของแพลตฟอร์ม** (เอกสารวิจัย 2.3) · ยกเลิก = ใบลดหนี้ ไม่ใช่ลบใบเดิม · เก็บสำเนา 5 ปี
ตอนเป็นแบบจำลอง ทุกใบมีแถบ **"ตัวอย่าง · ยังไม่ใช่เอกสารทางภาษี"** จนกว่าจะได้คำตอบ Q1

## T4 — ปิดหลังเที่ยงคืน (แผน 2026-10-03)

เจ้าของสั่ง "ไม่ต้องอิงของเก่าเลย": หน้าเวลาเปิด-ปิดทำจาก artboard ล้วน (ไม่มีการ์ดเวลาผ่อนผัน/วันเริ่มใช้/ใช้กับทุกสาขา) และต้องปิดหลังเที่ยงคืนได้จริง

**กฎเดียว: วันของสนามเริ่มที่ "ชั่วโมงเริ่มวัน" ของสนาม ไม่ใช่เที่ยงคืน**
- ปิดได้ถึง 24 + 6 (06:00 ของวันถัดไป) · ชั่วโมงหลังเที่ยงคืนเก็บเป็นชั่วโมง 24, 25, … ของวันที่เปิดร้าน (`BangkokHour(วัน, 25)` = ตี 1 ของวันถัดไป ใช้ได้อยู่แล้ว)
- ชั่วโมงเริ่มวันของสนาม = ส่วนที่เลยเที่ยงคืนมากที่สุดของสัปดาห์ (ปิด 26 → วันเริ่ม 02:00) · ไม่มีวันไหนข้ามเที่ยงคืน = 0 = เหมือนเดิมทุกอย่าง
- ห้ามวันไหนเปิดก่อนชั่วโมงเริ่มวัน (ไม่งั้นตีหนึ่งวันเสาร์เป็นของสองวัน)
- ทุกที่ที่ตัดวันเป็นเที่ยงคืนถึงเที่ยงคืน → ตัดที่ชั่วโมงเริ่มวันของสนาม · ทุกที่ที่แปลงเวลาเป็น (วัน, ชั่วโมง) → ใช้ตัวแปลงเดียวที่รู้ชั่วโมงเริ่มวัน
- รายได้/อัตราการใช้/ปิดยอด/คอมมิชชัน ของชั่วโมงหลังเที่ยงคืนนับเป็นของวันที่เปิดร้าน (ตาม artboard)
- หน้าจอแสดง 25 เป็น "01:00" และบอกว่าเป็นของวันถัดไป

ลำดับ: backend (กฎ + ทุกจุดที่ตัดวัน + test) → หน้าจอ (หน้าเวลาเปิด-ปิดตาม artboard, ตารางราคา, ไทม์ไลน์, ตอนนี้, รายการจอง, walk-in) → verify script → PR เดียว
