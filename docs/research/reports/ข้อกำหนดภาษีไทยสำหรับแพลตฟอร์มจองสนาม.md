# เอกสารภาษีของ CourtPaka: ตัวบทบอกอะไร และอะไรต้องถามสรรพากร

> เอกสารนี้เป็น **งานวิจัยเพื่อเตรียมบทสนทนากับนักบัญชี** ไม่ใช่คำแนะนำทางกฎหมายหรือทางภาษี และไม่ใช้แทนความเห็นของผู้สอบบัญชีหรือข้อหารือของกรมสรรพากร

ทุกข้อความในรายงานนี้ติดป้ายไว้สองแบบ: **[ตัวบท]** = ตัวบทกฎหมาย ประกาศอธิบดี คำสั่งกรมสรรพากร แบบแนบท้าย หรือข้อหารือที่เผยแพร่ พร้อมลิงก์ rd.go.th / ราชกิจจานุเบกษา · **[ตีความ]** = การอ่านของสำนักงานบัญชี ผู้เขียนบทความ หรือของผู้ทำวิจัยเอง — **ห้ามอ่าน [ตีความ] เป็นข้อยุติ** และห้ามเลื่อนขึ้นเป็นข้อสรุปในเอกสารที่ส่งให้ใคร

**คำตอบสั้นที่สุดของ Q1 คือ: โครงเอกสารของ PRD หัวข้อ 7 ถูกทางแล้วเป็นส่วนใหญ่ แต่มีสามจุดที่ต้องแก้ก่อนเขียนโค้ด และสามจุดที่ยังตอบไม่ได้เลยด้วยแหล่งที่เผยแพร่**  จุดที่ต้องแก้: (1) **ราคาบนหน้าจอของสนามที่จด VAT ต้องเป็นราคารวม VAT แล้ว** เพราะมาตรา 86/6 วรรคแรกบังคับไว้กับกิจการค้าปลีก ไม่ใช่ทางเลือกของสนาม [ตัวบท] ([rd.go.th/5208.html](https://www.rd.go.th/5208.html)) (2) **การยกเลิกการจองต้องเดินทางใบลดหนี้ ไม่ใช่ "ยกเลิกเอกสารเดิม"** เพราะประกาศอธิบดีฯ VAT ฉบับที่ 82 ข้อ 2(2) และ 2(6) ให้เหตุไว้ตรงตัวสำหรับการคืนเงินมัดจำ/เงินจอง และการไม่มีการให้บริการตามสัญญา [ตัวบท] ([rd.go.th/3380.html](https://www.rd.go.th/3380.html)) (3) **มัดจำทำให้เกิดเอกสารสองใบต่อการจองหนึ่งรายการ** เพราะ ป.73/2541 ระบุว่าความรับผิด VAT ของการให้บริการเกิด "ในขณะได้รับชำระเงิน" มัดจำ/เงินจอง [ตัวบท] ([rd.go.th/3580.html](https://www.rd.go.th/3580.html)) จุดที่ยังตอบไม่ได้: **คอร์ทรายชั่วโมงเป็น "ค่าเช่า" หรือ "ค่าบริการ"** (ตัวนี้ตัดสินทั้งว่าต้องเสีย VAT ไหมและหัก ณ ที่จ่าย 3% หรือ 5%) · **การริบมัดจำจาก no-show เสีย VAT หรือไม่** · และ **แพลตฟอร์มที่ไม่ได้รับเงินแทนสนามมีฐานอะไรให้ออกเอกสารในนามสนาม** — ทั้งสามข้อไม่มีข้อหารือที่เผยแพร่ตรงกรณี และควรยื่นข้อหารือหรือให้นักบัญชีตัดสินก่อนเขียน US-07 / US-16 / US-21

## 1. บทสรุปสำหรับผู้ตัดสินใจ

สิ่งที่งานวิจัยรอบนี้เปลี่ยนไปจากสมมติฐานใน PRD มีไม่มาก แต่ทุกข้อที่เปลี่ยนแตะโครงข้อมูล ไม่ใช่แค่ template เอกสาร

ข้อแรกและหนักที่สุดคือ **สถานะ VAT ของสนามไม่ใช่ boolean** สนามที่รายรับข้ามเส้น 1.8 ล้านบาทกลางปีต้องยื่น ภ.พ.01 และกลายเป็นผู้ประกอบการจดทะเบียนตั้งแต่วันหนึ่ง โดยเอกสารที่ออกไปก่อนวันนั้นไม่กลายเป็นใบกำกับภาษีย้อนหลัง [ตีความ] ⇒ คอลัมน์ต้องมีวันที่เริ่มมีผล และเอกสารต้อง snapshot กฎ ณ วันรับเงิน แบบเดียวกับที่ระบบทำกับ `PriceList` และ `CancellationPolicy` อยู่แล้ว

ข้อที่สองคือ **สนามที่ไม่จด VAT ต้องไม่มีทางในระบบที่จะผลิตเอกสารซึ่งมีคำว่า "ใบกำกับภาษี" หรือบรรทัด VAT ได้เลย** — ไม่ใช่เพราะเป็น UX ที่ดี แต่เพราะมาตรา 86/13 ห้ามไว้ตรงตัว และผลของการฝ่าฝืนคือรับผิดใน VAT ตามจำนวนในเอกสารเสมือนเป็นผู้ประกอบการจดทะเบียน + เบี้ยปรับ 2 เท่า + เงินเพิ่ม 1.5%/เดือน + โทษอาญาระดับจำคุก [ตัวบท + ตีความผสม ดูรายละเอียดข้อ 2.2] นี่เป็น hard constraint ระดับ schema ไม่ใช่ข้อความเตือนในหน้าตั้งค่า

ข้อที่สามคือ **แพลตฟอร์มควรวางตัวเป็น "ระบบที่สนามใช้ออกเอกสารเอง" ไม่ใช่ "ตัวแทนที่ออกเอกสารแทนสนาม"** เพราะเส้นทางตัวแทนที่ครอบ "ค่าบริการ" อย่างชัดแจ้ง (มาตรา 86/5(4) + ประกาศอธิบดีฯ ฉบับที่ 68) ถูกสร้างบนข้อเท็จจริงว่าตัวแทนเป็นผู้ **รับชำระเงิน** แทนตัวการ ซึ่ง CourtPaka ไม่ได้ทำ (ผู้จองโอน PromptPay เข้าสนามตรง) [ตัวบท + ตีความ] การเลือกทางนี้มีผลทางโค้ดทันที: **เลข running แยกต่อสนาม** และ **ห้ามมีชื่อ/เลขผู้เสียภาษีของแพลตฟอร์มบนเอกสาร** เพราะการใส่ลงไปคือการประกาศตัวเป็นตัวแทนตามมาตรา 86/4 วรรคท้าย ซึ่งลากเงื่อนไขทั้งชุดของประกาศฯ 8/68 เข้ามา

ข้อที่สี่คือเรื่องที่ PRD ยังไม่มี: **ลูกค้านิติบุคคลจะหักภาษี ณ ที่จ่าย 3% หรือ 5% จากยอดที่โอนให้สนาม** ⇒ สลิปจะมายอดไม่เท่า QR และสมมติฐาน "ยอดสลิป = ยอด QR" ที่ระบบสร้างไว้จะพังในกรณีนี้ [ตีความ] ⇒ นี่เป็นการตัดสินใจเชิงผลิตภัณฑ์ที่ต้องยกให้ทีม ไม่ใช่บั๊กที่แก้ได้ในโค้ด

ตารางสรุปสถานะของแต่ละหัวข้อที่ Q1 ถาม:

| ประเด็นของ Q1 | สถานะ | ความมั่นใจ |
|---|---|---|
| รายการบังคับของใบกำกับภาษีอย่างย่อ / เต็มรูป | **ตอบได้** จากมาตรา 86/6, 86/4 + ประกาศฯ 199 | สูง (ตัวบท) |
| สนามแบดมินตันมีสิทธิออกอย่างย่อไหม | **ตอบได้แค่ระดับตีความ** — ประกาศฯ 32 ใช้คำว่า "เช่น" ไม่มีข้อหารือที่พูดถึงสนามกีฬาตรงตัว | ปานกลาง |
| เอกสารของสนามที่ไม่จด VAT | **ตอบได้** ใบรับตามมาตรา 105 + 105 ทวิ 6 รายการ เก็บ 5 ปี ไม่ติดอากรแสตมป์ | สูง (ตัวบท) |
| การออกเอกสารแทนสนาม | **ตอบได้ว่าทางไหนปลอดภัยกว่า** แต่ฐานกฎหมายของทางที่เลือกยังไม่มีคำยืนยัน | ต่ำ — ต้องหารือ |
| ใบลดหนี้ vs ยกเลิกเอกสาร | **ตอบได้** ใบลดหนี้ (ประกาศฯ 82 ข้อ 2(2), 2(6)) และต้องออกในเดือนภาษีที่เหตุเกิด | สูง (ตัวบท) |
| รายงานภาษีขาย: คอลัมน์ | **ตอบได้ครบ** 7 คอลัมน์ + 3 ฟิลด์หัวรายงาน จากแบบแนบท้ายของกรมสรรพากรเอง | สูง (ตัวบท) |
| ระยะเวลาเก็บเอกสาร | **ตอบได้** 5 ปีตามมาตรา 87/3 (อธิบดีขยายได้ถึง 7 · เลิกกิจการเก็บต่อ 2) | สูง (ตัวบท) |
| VAT ของค่าคอมมิชชัน | **ตอบได้** ฐานภาษี = ค่าคอมมิชชันเท่านั้น ตามมาตรา 79 | สูง (ตัวบท + ข้อหารือใกล้เคียง) |
| หัก ณ ที่จ่ายของค่าคอมมิชชัน | **ตอบได้เฉพาะกรณีแพลตฟอร์มเป็นบริษัท** (3%) กรณีบุคคลธรรมดาแหล่งขัดกัน | ปานกลาง / ต่ำ |
| คอร์ทรายชั่วโมง: เช่าหรือบริการ | **ตอบไม่ได้** และเป็นคำถามที่อยู่ก่อนทุกอย่างในรายงานนี้ | ต้องหารือ |
| ริบมัดจำ no-show เสีย VAT ไหม | **ตอบไม่ได้** สองการตีความขัดกันและทั้งคู่มีฐาน | ต้องหารือ |

## 2. ข้อสรุปรายประเด็น

### 2.1 ใบกำกับภาษีอย่างย่อ (ม.86/6) กับเต็มรูป (ม.86/4) — ต่างกันที่ผู้ซื้อและที่การแยก VAT

**[ตัวบท]** มาตรา 86/6 ให้สิทธิ (ไม่ใช่หน้าที่) ออกใบกำกับภาษีอย่างย่อแก่ **ผู้ประกอบการจดทะเบียนที่ประกอบกิจการค้าปลีก** ตามลักษณะและเงื่อนไขที่อธิบดีกำหนด และห้าม **ตัวแทน** ของผู้ประกอบการจดทะเบียนออกใบกำกับภาษีอย่างย่อ ([rd.go.th/5208.html](https://www.rd.go.th/5208.html)) รายการบังคับมีเจ็ดข้อ: คำว่า "ใบกำกับภาษี" ในที่เห็นได้เด่นชัด · ชื่อหรือชื่อย่อและเลขประจำตัวผู้เสียภาษีของผู้ออก · หมายเลขลำดับของใบกำกับภาษี (และของเล่ม ถ้ามี) · ชื่อ ชนิด ประเภท ปริมาณ และมูลค่าของสินค้าหรือบริการ · **ราคาที่มีข้อความระบุชัดเจนว่าเป็นราคาที่รวมภาษีมูลค่าเพิ่มไว้แล้ว** · วันเดือนปีที่ออก · และข้อความอื่นที่อธิบดีกำหนด ([rd.go.th/5208.html](https://www.rd.go.th/5208.html)) จุดที่ต่างจากเต็มรูปอย่างมีนัยคือ **ไม่ต้องมีชื่อ-ที่อยู่ผู้ซื้อ และไม่ต้องแยกจำนวน VAT**

**[ตัวบท]** วรรคแรกของมาตรา 86/6 บังคับด้วยว่าในกิจการค้าปลีก **ราคาสินค้าหรือค่าบริการที่แสดงต้องเป็นราคาที่รวม VAT แล้ว** ([rd.go.th/5208.html](https://www.rd.go.th/5208.html)) — ข้อนี้ไม่ใช่เรื่องของเอกสาร แต่เป็นเรื่องของหน้าจอ: ถ้าสนามที่จด VAT ตั้งราคา 300 บาท/ชม. ราคานั้นต้องหมายถึงรวม VAT แล้ว ไม่ใช่ 300 + VAT [ตีความ]

**[ตัวบท]** ฝั่งเต็มรูป มาตรา 86/4 กำหนดแปดรายการ โดยเพิ่มจากอย่างย่อคือ **ที่อยู่ของผู้ออก** · **ชื่อและที่อยู่ของผู้ซื้อ (บังคับทุกกรณี)** · และ **จำนวน VAT ที่แยกออกจากมูลค่าให้ชัดแจ้ง** ([rd.go.th/5208.html](https://www.rd.go.th/5208.html)) และ **ประกาศอธิบดีฯ VAT ฉบับที่ 199 ลงวันที่ 26 ธันวาคม 2556** ออกตามมาตรา 86/4 (8) เพิ่มให้ต้องระบุ **เลขประจำตัวผู้เสียภาษีของผู้ซื้อ "ซึ่งเป็นผู้ประกอบการจดทะเบียน"** และข้อความ "สำนักงานใหญ่" (หรือ สนญ./HO/HQ) หรือ "สาขาที่ …" ตามที่ปรากฏใน ภ.พ.20 หรือเป็น **รหัสตัวเลขห้าหลัก** (00000 = สำนักงานใหญ่) ใช้กับใบกำกับภาษีที่จัดทำตั้งแต่ **1 มกราคม 2558** ([rd.go.th/27982.html](https://www.rd.go.th/27982.html)) ฉบับก่อนหน้าคือฉบับที่ 196 ลงวันที่ 28 พฤษภาคม 2556 ซึ่งใช้กับเอกสารตั้งแต่ 1 มกราคม 2557 ([rd.go.th/48266.html](https://www.rd.go.th/48266.html))

**[ตัวบท]** คำชี้แจงกรมสรรพากรเรื่องการระบุเลขประจำตัวผู้เสียภาษีระบุสามเรื่องที่กระทบการออกแบบฟอร์มโดยตรง: ผู้ขายต้องระบุเลขผู้เสียภาษีของผู้ซื้อ **เฉพาะเมื่อผู้ซื้อเป็นผู้ประกอบการจดทะเบียน** · **บุคคลธรรมดาที่ซื้อไปใช้เองไม่ต้องแจ้ง** · และมี **safe harbour**: ถ้าผู้ขายได้แจ้งลูกค้าแล้ว (ป้าย จดหมาย หรือ **ประกาศบนเว็บไซต์**) ขอให้แจ้งเลขผู้เสียภาษี แล้วลูกค้าไม่แจ้ง ผู้ขายไม่ต้องรับผิดจากใบกำกับภาษีที่รายการไม่ครบ ([rd.go.th/49981.html](https://www.rd.go.th/49981.html)) **[ตีความ]** safe harbour ข้อนี้แปลว่าข้อความ "กรุณาแจ้งเลขผู้เสียภาษีถ้าต้องการใบกำกับภาษีเต็มรูป" บนหน้าจอจองมีผลทางกฎหมายต่อสนาม ไม่ใช่แค่ UX

**สนามแบดมินตันมีสิทธิออกอย่างย่อไหม** — **[ตัวบท]** ประกาศอธิบดีฯ VAT **ฉบับที่ 32** (ลงนาม 8 เมษายน 2535 ใช้บังคับย้อนไปถึง 1 มกราคม 2535 และยกเลิกฉบับที่ 6) กำหนดลักษณะและเงื่อนไขของกิจการขายปลีก **หรือกิจการให้บริการในลักษณะบริการรายย่อยแก่บุคคลจำนวนมาก** ให้เป็นกิจการค้าปลีกตามมาตรา 86/6 โดยตัวอย่างฝั่งบริการที่ประกาศระบุไว้คือ **ภัตตาคาร โรงแรม การซ่อมแซมทุกชนิด โรงภาพยนตร์** และประกาศยังบังคับว่า **เมื่อผู้รับบริการเรียกร้อง ผู้ประกอบการต้องจัดทำใบกำกับภาษีที่มีรายการครบตามมาตรา 86/4** ([rd.go.th/3402.html](https://www.rd.go.th/3402.html)) **[ตีความ]** สำนักงานบัญชีไทยหลายแห่งอ่านว่าบริการสนามกีฬาและฟิตเนสที่ให้บริการแก่คนจำนวนมากเข้าข่าย "บริการรายย่อยแก่บุคคลจำนวนมาก" และออกอย่างย่อได้ ([PNK Accounting](https://pnkaccount.co.th/%E0%B9%83%E0%B8%9A%E0%B8%81%E0%B8%B3%E0%B8%81%E0%B8%B1%E0%B8%9A%E0%B8%A0%E0%B8%B2%E0%B8%A9%E0%B8%B5%E0%B8%AD%E0%B8%A2%E0%B9%88%E0%B8%B2%E0%B8%87%E0%B8%A2%E0%B9%88%E0%B8%AD/), [BeeAccountant](https://www.beeaccountant.com/abbtaxinvoice/)) — **แต่ไม่พบข้อหารือของกรมสรรพากรที่พูดถึงสนามแบดมินตันหรือสนามกีฬารายชั่วโมงตรงตัว** ข้อสนับสนุนเชิงเทียบเคียงที่เป็นตัวบทมีอยู่ชิ้นเดียว คือ **ประกาศฯ ฉบับที่ 154** ซึ่งออกตามมาตรา 86/8 (คนละมาตรา) และระบุ "การแสดงหรือการเล่นกีฬาที่เก็บค่าเข้าดู/ค่าเข้าชม" เป็นกิจการรายย่อยกลุ่มหนึ่ง ([rd.go.th/14897.html](https://www.rd.go.th/14897.html))

**[ตีความ]** สิทธิออกอย่างย่อเกิดจากลักษณะกิจการ ไม่ใช่จากใบอนุญาต จึงไม่ต้องยื่นขออนุมัติล่วงหน้า **เว้นแต่จะออกด้วยเครื่องบันทึกการเก็บเงิน/POS ซึ่งต้องยื่น ภ.พ.06** ตามประกาศฯ ฉบับที่ 46 — ข้อหลังนี้มาจากบทความสำนักงานบัญชี ([BeeAccountant](https://www.beeaccountant.com/abbtaxinvoice/)) ประกอบตัวประกาศที่ [rd.go.th/3394.html](https://www.rd.go.th/3394.html) ยังไม่ได้ตรวจทีละข้อ ⇒ **แพลตฟอร์มควรถามสนามตอนตั้งค่าว่าใช้ POS หรือไม่ และได้อนุมัติ ภ.พ.06 หรือยัง**

**ออกอย่างย่อไปแล้ว ลูกค้าขอเต็มรูปภายหลัง** — **[ตัวบท]** วิธีที่วงการยึดคือแนวของ **ป.86/2542 ข้อ 25**: เรียกคืนใบกำกับภาษีฉบับเดิม ประทับตราหรือขีดฆ่าว่า "ยกเลิก" เก็บรวมไว้กับสำเนา · จัดทำฉบับใหม่ที่เป็น **เลขที่ใหม่ แต่ลงวันเดือนปีให้ตรงกับฉบับเดิม** · และหมายเหตุในฉบับใหม่ว่าเป็นการยกเลิกและแทนฉบับเดิมเลขที่ใด ([rd.go.th/3568.html](https://www.rd.go.th/3568.html)) **[ตีความ]** แต่ ป.86/2542 เป็นหลักเกณฑ์สำหรับใบกำกับภาษี**เต็มรูป** การนำข้อ 25 มาใช้กับกรณี "ย่อ → เต็ม" เป็นการใช้โดยอนุโลมตามแนวปฏิบัติ ไม่ใช่ตัวบทที่เขียนถึงกรณีนี้ตรงตัว — และขอบเขตของ ป.86/2542 เองยังมีแหล่งที่ระบุไม่ตรงกัน (ดูข้อ 3) **[ตัวบท]** มาตรา 86/12 (ใบแทน) **ไม่ใช่** ทางนี้ เพราะใบแทนใช้เมื่อผู้ซื้อทำเอกสารสูญหาย ถูกทำลาย หรือชำรุดในสาระสำคัญ ([rd.go.th/5208.html](https://www.rd.go.th/5208.html))

**[ตีความ]** ข้อบังคับ "ต้องเรียกคืนฉบับเดิม" เป็นปัญหาโดยธรรมชาติกับเอกสารที่ส่งเป็น PDF/อีเมล ทางออกที่สะอาดกว่าคือ **ถามตอนจองว่าต้องการเต็มรูปหรือไม่ แล้วออกเต็มรูปตั้งแต่ต้น** ซึ่งตัดทั้งการเรียกคืนและการออกย้อนวันเดิมออกไปทั้งก้อน

**ส่ง PDF ทางอีเมลถือเป็นใบกำกับภาษีไหม** — **[ตัวบท]** ป.86/2542 มีหลักเกณฑ์สำหรับใบกำกับภาษีที่ **จัดทำด้วยระบบคอมพิวเตอร์** โดยรายการที่เป็นสาระสำคัญต้องตีพิมพ์/พิมพ์ขึ้นด้วยระบบเดียวกัน ([rd.go.th/3568.html](https://www.rd.go.th/3568.html)) ส่วนใบกำกับภาษี **อิเล็กทรอนิกส์** อยู่ภายใต้ **ประกาศอธิบดีกรมสรรพากร (ฉบับที่ 15) ลงวันที่ 18 ตุลาคม 2562** ซึ่งนิยามใบรับอิเล็กทรอนิกส์ว่าต้องเป็นข้อมูลอิเล็กทรอนิกส์ที่ **ลงลายมือชื่อดิจิทัล** ([ตัวประกาศ PDF](https://www.rd.go.th/fileadmin/user_upload/kormor/newlaw/dgg15.pdf)) และระเบียบเดิมสามฉบับ (รวมระเบียบ e-Tax Invoice by Email พ.ศ. 2560) ถูกยกเลิกไปแล้ว โดยฉบับ by Email ถูกยกเลิกด้วย **พ.ร.บ.แก้ไขเพิ่มเติมประมวลรัษฎากร (ฉบับที่ 53) พ.ศ. 2564** ([rd.go.th/60046.html](https://www.rd.go.th/60046.html)) **[ตีความ]** สิ่งที่กฎหมายรับรองจึงไม่ใช่ "การเป็นไฟล์" แต่คือ "ลายมือชื่อดิจิทัล + อยู่ในระบบที่ขึ้นทะเบียน" ⇒ **PDF ที่ส่งทางอีเมลโดยไม่อยู่ในระบบใดเลยเป็นได้แค่ภาพสำเนาของใบกำกับภาษีกระดาษ** — ข้อสรุปนี้เป็นการอนุมานจากโครงสร้างประกาศ ไม่ใช่ถ้อยคำที่ยกมาได้

### 2.2 สนามที่ไม่จด VAT: ออกใบรับตามมาตรา 105 และห้ามแตะคำว่า "ใบกำกับภาษี"

**[ตัวบท]** มาตรา 105 วรรคแรกบังคับให้ผู้รับเงินออกใบรับ "ในทันทีทุกคราวที่รับเงินหรือรับชำระราคา **ไม่ว่าจะมีการเรียกร้องให้ออกใบรับหรือไม่ก็ตาม**" โดยหน้าที่นี้เกิดเมื่อเงินที่รับแต่ละครั้งเกินจำนวนที่อธิบดีกำหนด — ผู้จด VAT/SBT อยู่ใน 105(1) ซึ่งตัวบทกำหนดเพดานว่าอธิบดี "จะกำหนดเกินหนึ่งพันบาทไม่ได้" ส่วนกรณีอื่น (รวมสนามที่ไม่จด VAT) อยู่ใน 105(2) ซึ่งเพดานคือหนึ่งหมื่นบาท ([มาตรา 105](https://deka.in.th/laws/rvc/105) · ตัวบทเดียวกันที่ [rd.go.th/5203.html](https://www.rd.go.th/5203.html)) และถ้ารับเป็นหลายงวด ตัวบทสั่งว่า "**ให้ออกใบรับทุกคราวในทันทีที่รับเงิน**" ([มาตรา 105](https://deka.in.th/laws/rvc/105)) **[ตัวบท]** มาตรา 106 บังคับต่อว่าเมื่อ **ผู้มีส่วนได้เสียเรียกร้อง** ผู้มีหน้าที่ออกใบรับต้องออกให้ทันที **ไม่ว่าจำนวนเงินจะถึงเกณฑ์ตามมาตรา 105 หรือไม่** ([rd.go.th/5203.html](https://www.rd.go.th/5203.html))

**[ตีความ]** ค่าคอร์ทรายชั่วโมงเกือบทุกใบต่ำกว่าเกณฑ์ของ 105(2) ⇒ หน้าที่ "ออกทุกครั้งโดยไม่ต้องรอให้ขอ" แทบไม่ถูกกระตุ้น แต่หน้าที่ตามมาตรา 106 ถูกกระตุ้น **ทุกครั้ง** ที่ลูกค้ากดขอ ⇒ ในทางระบบให้ถือว่า "ต้องออกได้เสมอเมื่อผู้จ่ายกดขอ" เป็นข้อบังคับ ไม่ใช่ feature เสริม

**[ตัวบท]** รายการบังคับบนใบรับตามมาตรา 105 ทวิ มีหกข้อ: เลขประจำตัวผู้เสียภาษีของผู้ออก · ชื่อหรือยี่ห้อของผู้ออก · **เลขลำดับของเล่มและของใบรับ** · วันเดือนปี · จำนวนเงินที่รับ · และชนิด ชื่อ จำนวน ราคาสินค้าเฉพาะชนิดที่ราคาตั้งแต่ 100 บาทขึ้นไป · โดยต้องทำ **ต้นขั้วหรือสำเนาเก็บไว้ไม่น้อยกว่าห้าปี** และข้อความต้องเป็นตัวเลขไทยหรืออารบิกและอักษรไทย ([tax-ez.info — ม.105 ทวิ](https://tax-ez.info/Revenue/View/ZBeQXD8G/) ยืนยันโดย [rd.go.th/5203.html](https://www.rd.go.th/5203.html)) **[ตัวบท]** โทษตามมาตรา 127 ทวิ ครอบ "ไม่ออกใบรับให้ในทันทีที่รับเงิน" และ "ออกใบรับเป็นจำนวนเงินน้อยกว่าที่รับจริง" ปรับไม่เกิน 500 บาท หรือจำคุกไม่เกิน 1 เดือน หรือทั้งสอง ([rd.go.th/5203.html](https://www.rd.go.th/5203.html))

**[ตัวบท]** มาตรา 86/13 วรรคแรกห้ามเด็ดขาด: "ห้ามมิให้บุคคลซึ่งมิใช่ผู้ประกอบการจดทะเบียนหรือมิใช่ผู้มีสิทธิออกใบกำกับภาษีได้ตามหมวดนี้ ออกใบกำกับภาษี ใบเพิ่มหนี้ หรือใบลดหนี้" และผู้ฝ่าฝืน "ต้องรับผิดในภาษีมูลค่าเพิ่มตามจำนวนที่ปรากฏในใบกำกับภาษี … **เสมือนเป็นผู้ประกอบการจดทะเบียน**" ([Legardy — ม.86–86/14](https://legardy.com/thai-law/revenue-code/revenue-code-vat-tax-invoices-section-86-14) · [ThaiDeka ม.86/13](https://deka.in.th/laws/rvc/86/13)) และคู่มือใบกำกับภาษีของกรมสรรพากรยืนยันว่าผู้ประกอบการที่มิได้จดทะเบียน แม้ประกอบกิจการที่อยู่ในบังคับต้องเสีย VAT ก็ไม่มีสิทธิออกใบกำกับภาษี ([คู่มือใบกำกับภาษี PDF](https://www.rd.go.th/fileadmin/user_upload/ebook/taxinvoice.pdf)) **[ตีความจากการอ้างของกรมสรรพากรผ่านสื่อ — ยังไม่ได้ตัวบท verbatim]** ผลเพิ่มเติมที่กรมสรรพากรระบุคือ **เบี้ยปรับ 2 เท่าของภาษีตามใบกำกับภาษี + เงินเพิ่ม 1.5% ต่อเดือน** และโทษอาญาตามมาตรา 90/4(3) **จำคุก 3 เดือน – 7 ปี และปรับ 2,000 – 200,000 บาท** โดยนับเป็นกระทงต่อใบ ([InfoQuest อ้างกรมสรรพากร](https://www.infoquest.co.th/2024/375463) · [ThaiLawConsult](https://www.thailawconsult.com/nasid32.html) · [Workpoint Today](https://workpointtoday.com/สรรพากรเชือด-ซื้อ-ขายใบ/))

**[ตีความ]** สิ่งที่ถูกห้ามไม่ใช่ชื่อเอกสาร "ใบเสร็จรับเงิน" แต่คือลักษณะของ "ใบกำกับภาษี" — คำว่า *ใบกำกับภาษี* บนเอกสาร และ/หรือบรรทัด VAT 7% ⇒ สนามที่ไม่จด VAT ออกใบเสร็จรับเงินได้ตามปกติ (และมีหน้าที่ต้องออกอยู่แล้วตามมาตรา 105) แต่ห้ามมีสองสิ่งนั้น · ในทางเดียวกัน **หน้าจอราคาของสนามที่ไม่จด VAT ไม่ควรมีข้อความ "รวม VAT แล้ว"** เพราะเป็นการแสดงว่ามีการเรียกเก็บ VAT

**อากรแสตมป์** — **[ตัวบท]** ลักษณะตราสาร 28 "ใบรับ" ในบัญชีอัตราอากรแสตมป์ครอบเพียงสามกรณี: ใบรับรางวัลสลากกินแบ่งรัฐบาล · ใบรับสำหรับการโอนหรือก่อตั้งสิทธิเกี่ยวกับอสังหาริมทรัพย์ที่นิติกรรมมีการจดทะเบียน · และใบรับสำหรับการขาย ขายฝาก ให้เช่าซื้อ หรือโอนกรรมสิทธิ์ยานพาหนะที่จดทะเบียน โดยอัตรา 1 บาทต่อทุก 200 บาทหรือเศษของ 200 บาท เฉพาะใบรับตั้งแต่ 200 บาทขึ้นไป และมีข้อยกเว้นให้ใบรับสำหรับจำนวนเงินที่ผู้รับต้องเสีย VAT/SBT ([rd.go.th/6162.html](https://www.rd.go.th/6162.html)) **[ตีความ]** ใบเสร็จค่าคอร์ทไม่เข้าทั้งสามอนุ ⇒ **ไม่ต้องติดอากรแสตมป์** ทั้งกรณีจดและไม่จด VAT · แต่อย่าสับสนกับ **ลักษณะ 1 (เช่าที่ดิน โรงเรือน สิ่งปลูกสร้าง)** ซึ่งเก็บอากรจาก **สัญญาเช่า** ไม่ใช่จากใบรับ ⇒ ถ้าสนามทำสัญญาเช่าพื้นที่เป็นลายลักษณ์อักษร (เช่น ให้เช่าคอร์ทระยะยาว หรือให้โค้ชเช่าพื้นที่สอน) ตราสารนั้นอาจมีอากรของตัวเอง ซึ่งยังไม่ได้ตรวจ

**ลูกค้านิติบุคคลใช้ใบเสร็จของสนามที่ไม่จด VAT เป็นรายจ่ายได้ไหม** — **[ตีความ — ไม่มีตัวบทหรือข้อหารือยืนยันตรงประเด็น]** เงื่อนไขของมาตรา 65 ตรี (18) คือ "พิสูจน์ผู้รับได้" ไม่ใช่ "มีใบกำกับภาษี" ⇒ สิ่งที่ลูกค้าเสียคือภาษีซื้อ 7% ที่เครดิตไม่ได้ ไม่ใช่สิทธิลงรายจ่าย ([FlowAccount](https://flowaccount.com/blog/prohibited-expenses-related-tax-calculation/) · [dst.co.th](https://www.dst.co.th/index.php?option=com_content&view=article&id=5460%3Aarticledec25-8&catid=29&Itemid=180&lang=th) ประกอบตัวบทมาตรา 65 ตรี ที่ [rd.go.th/5939.html](https://www.rd.go.th/5939.html)) **ห้ามเขียนข้อนี้เป็นข้อสรุปเด็ดขาด** — ให้นักบัญชียืนยัน

**เกณฑ์ 1.8 ล้าน** — **[ตัวบท]** มาตรา 81/1 ยกเว้น VAT ให้กิจการขนาดย่อมตามมูลค่าฐานภาษีที่พระราชกฤษฎีกากำหนด โดยพระราชกฤษฎีกาจะกำหนดต่ำกว่า 600,000 บาท/ปีไม่ได้ ([rd.go.th/5206.html](https://www.rd.go.th/5206.html)) และ **พระราชกฤษฎีกา (ฉบับที่ 432) พ.ศ. 2548** กำหนดเกณฑ์ไว้ที่ **1.8 ล้านบาท/ปี** ([rd.go.th/22646.html](https://www.rd.go.th/22646.html)) **[ตีความ — จากแหล่งสำนักงานบัญชีที่สอดคล้องกันสามแหล่ง ยังไม่ได้ตัวบทมาตรา 85/1 verbatim]** ต้องยื่น ภ.พ.01 ภายใน **30 วันนับแต่วันที่รายรับเกิน 1.8 ล้าน** ([PEAK](https://www.peakaccount.com/blog/tax/gen-tax/tax-vat-registration) · [FlowAccount](https://flowaccount.com/blog/vat-basic-knowledge/) · [Inflow Account](https://inflowaccount.co.th/what-you-should-do-when-revenue-over-1-8-mb/)) และคู่มือประชาชนระบุว่าผู้มีหน้าที่จดแต่ไม่จดมีความผิดตามมาตรา 90/2 จำคุกไม่เกิน 1 เดือนหรือปรับไม่เกิน 5,000 บาท ([info.go.th](https://info.go.th/procedure/94e56d14-b7ae-4225-b9d7-83b1693863b6/view))

**[ตัวบท]** มีทางผ่อนผันที่น่าสนใจสำหรับสนามเล็กที่จด VAT แล้ว: **มาตรา 86/8 + ประกาศฯ ฉบับที่ 154** ให้ผู้ประกอบการจดทะเบียนที่ประกอบ "กิจการรายย่อย" (ฐานภาษีไม่เกิน 300,000 บาท/เดือน) **ไม่จำต้องออกใบกำกับภาษีสำหรับการขาย/ให้บริการที่มีมูลค่าครั้งหนึ่งไม่เกิน 1,000 บาท เว้นแต่ผู้ซื้อเรียกร้อง** โดยต้องจัดทำ **ใบกำกับภาษีรวมยอดรายวัน** เก็บเป็นเอกสารประกอบรายงานภาษีขาย ([rd.go.th/14897.html](https://www.rd.go.th/14897.html)) **[ตีความ]** การจองรายชั่วโมงหลักร้อยบาทจะต่ำกว่า 1,000 บาทเกือบทุกใบ แต่การจองหลายชั่วโมง/หลายคอร์ทในใบเดียวเกินได้ และยังไม่ยืนยันว่า "มูลค่าครั้งหนึ่ง" นับต่อการให้บริการหรือต่อรายการจอง

### 2.3 การออกเอกสารแทนสนาม: สามเส้นทางของกฎหมาย และเหตุที่ CourtPaka ไม่เข้าเส้นทางใดเลย

**[ตัวบท]** กฎหมายไทยมีสามเส้นทางที่ต่างกันโดยสิ้นเชิงสำหรับการให้คนอื่นออกใบกำกับภาษีในนามผู้ประกอบการจดทะเบียน

เส้นทาง A คือ **มาตรา 86 วรรคสี่** ("การออกใบกำกับภาษีโดยตัวแทนในนามของผู้ประกอบการจดทะเบียนให้เป็นไปตามหลักเกณฑ์ วิธีการ และเงื่อนไขที่อธิบดีกำหนด") ประกอบ **ประกาศอธิบดีฯ VAT ฉบับที่ 8** ซึ่งเป็นสัญญาตั้งตัวแทน **เพื่อขายตามประเภทของสินค้า** เงื่อนไขหกข้อคือ สัญญาเป็นลายลักษณ์อักษร · ตัวแทนได้รับค่าตอบแทนจากตัวการ · ทั้งสองฝ่ายเป็นผู้ประกอบการจดทะเบียนที่คำนวณภาษีตามมาตรา 82/3 · เก็บต้นฉบับสัญญาที่สำนักงานใหญ่ไม่น้อยกว่า 5 ปีหลังสัญญาสิ้นสุด · **ตัวการแจ้งสัญญาต่อเจ้าพนักงานสรรพากรภายใน 15 วัน** · และตัวแทนทำรายงานสินค้าแยกตามมาตรา 87(3) ([rd.go.th/3414.html](https://www.rd.go.th/3414.html) ประกอบ [rd.go.th/5208.html](https://www.rd.go.th/5208.html))

เส้นทาง B คือ **มาตรา 86/5(4)** ประกอบ **ประกาศอธิบดีฯ VAT ฉบับที่ 68 ลงวันที่ 25 ธันวาคม 2538** ซึ่งเป็นการตั้งตัวแทนให้ **รับชำระเงินค่าสินค้าหรือค่าบริการ** และออกใบกำกับภาษีแทนตัวการ — **เส้นทางเดียวที่ครอบ "ค่าบริการ" อย่างชัดแจ้ง** ([ชื่อเรื่องเต็มที่ห้องสมุดรัฐสภา](https://dl.parliament.go.th/handle/20.500.13072/100979) · [rd.go.th/3390.html](https://www.rd.go.th/3390.html)) และมีข้อหารือรับรองว่าใช้กับค่าบริการได้จริง: **ข้อหารือ กค 0811/พ./7986 (20 สิงหาคม 2544)** กรณีรัฐวิสาหกิจให้ **ธนาคาร** รับชำระค่าสาธารณูปโภคแล้วออกใบกำกับภาษีแทน กรมสรรพากรวินิจฉัยว่าทำได้โดยตั้งธนาคารเป็นตัวแทนตามมาตรา 86/5(4) และย้ำว่าประกาศ **ไม่ได้บังคับ** ให้ต้องทำสัญญาตั้งตัวแทนเพียงเพราะเข้าเงื่อนไข ([rd.go.th/25328.html](https://www.rd.go.th/25328.html))

เส้นทาง C คือ **มาตรา 86/2** สำหรับตัวการที่อยู่ **นอกราชอาณาจักร** ซึ่งเป็นกรณีเดียวที่ตัวบทระบุว่าต้อง **ยื่นคำขออนุมัติต่ออธิบดี** และตัวแทนที่ได้รับอนุมัติ "มีหน้าที่และความรับผิดเช่นเดียวกับผู้ประกอบการจดทะเบียน" ([rd.go.th/5208.html](https://www.rd.go.th/5208.html))

**[ตัวบท]** ถ้าเดินเส้นทางตัวแทนจริง เอกสารจะเปลี่ยนรูปสองอย่าง: **ป.86/2542 ข้อ 5** กำหนดให้ตัวแทนใช้ **แบบพิมพ์ใบกำกับภาษีของตัวแทน** โดยระบุชื่อ ที่อยู่ เลขประจำตัวผู้เสียภาษีของ **ตัวการ** ([rd.go.th/3568.html](https://www.rd.go.th/3568.html)) และ **มาตรา 86/4 วรรคท้าย** บังคับให้ระบุของ **ตัวแทน** ด้วย ⇒ มีเลขผู้เสียภาษีสองชุดบนหน้าเดียวกัน ([มาตรา 86/4 และ 86/6 PDF](https://www.rd.go.th/fileadmin/images/image_pramoun/mata86_4_6.pdf)) ส่วนความผิดเรื่องรายการในใบกำกับภาษีมีโทษตามมาตรา 90(12) ([ป.86/2542](https://www.rd.go.th/3568.html))

**[ตีความ]** สำหรับ CourtPaka ที่ผู้จองโอน PromptPay เข้าสนามตรง ข้อเท็จจริง **ไม่เข้าองค์ประกอบ "ตัวแทนรับชำระเงิน" ของประกาศฯ 68** เพราะแพลตฟอร์มไม่ได้รับเงินแทนสนามเลย และ **ไม่เข้าประกาศฯ 8** เพราะฉบับนั้นเขียนไว้สำหรับสินค้า ⇒ ฐานตามเส้นทางตัวแทนอ่อนหรือไม่มี ทางที่เหลือมีสองทาง: ตีความเป็นมาตรา 86 วรรคสี่ทั่วไปแล้วไปหาหลักเกณฑ์ที่ใช้บังคับ (ซึ่งมีแต่ฉบับที่ 8 ที่เขียนถึงสินค้า) หรือ **ออกแบบให้สนามเป็นผู้ออกเอกสารเอง โดยแพลตฟอร์มเป็นเพียงระบบ**

**[ตีความ]** ทางที่สองมีน้ำหนักมากกว่า เพราะกฎหมายกำกับที่ **"ผู้ออก" (ผู้ประกอบการจดทะเบียน)** ไม่ใช่ที่เครื่องมือหรือผู้พิมพ์ (มาตรา 86 วรรคหนึ่งผูกหน้าที่ไว้กับผู้ประกอบการจดทะเบียน และวรรคสี่เปิดข้อยกเว้นเฉพาะกรณีตัวแทน — [rd.go.th/5208.html](https://www.rd.go.th/5208.html)) และมีข้อหารือที่ใกล้เคียง: **กค 0811/พ./7637 (7 สิงหาคม 2546)** กรณีบริษัท A จัดทำใบแจ้งหนี้/ใบเสร็จที่บริษัท T มอบให้ทำ และเพิ่มชื่อของตนเองลงไป กรมสรรพากรวินิจฉัยว่าทำได้ เพราะเป็นการเพิ่มเติมข้อความมากกว่าที่กฎหมายกำหนด และใบกำกับภาษีมีรายการครบตามมาตรา 86/4 แล้ว ([rd.go.th/24640.html](https://www.rd.go.th/24640.html)) **แต่ไม่พบหนังสือหรือข้อหารือที่ยืนยันโดยตรงว่า "ผู้ให้บริการซอฟต์แวร์ที่สร้างเอกสารให้ผู้ประกอบการออกเอง ไม่ถือเป็นตัวแทนตามมาตรา 86 วรรคสี่"** — นี่คือคำถามข้อหารือข้อแรกในข้อ 3

**[ตัวบท]** ถ้าอนาคตแพลตฟอร์มอยากนำส่งข้อมูลให้กรมสรรพากรแทนสนาม จะต้องเดินเส้นทาง **Service Provider** ของระบบ e-Tax Invoice & e-Receipt ซึ่งมีวิธีนำส่งสามทาง (Upload / Service Provider / Host-to-Host) และมี **ETDA เป็นหน่วยรับรองระบบสารสนเทศ** ([กรมสรรพากร — Service Provider PDF](https://etax.rd.go.th/etax_staticpage/app/emag/flipbook_2567/pdf/09_Service-Provider.pdf) · [ETDA](https://standard.etda.or.th/serviceprovider/)) **[ตีความ]** นั่นเป็นภาระ compliance ระดับองค์กร ไม่ใช่ฟีเจอร์ ⇒ ควรถือเป็นเฟสหลัง

**สองเรื่องข้างเคียงที่ต้องรู้ไว้** — **[ตัวบท]** **พ.ร.ฎ. การประกอบธุรกิจบริการแพลตฟอร์มดิจิทัลที่ต้องแจ้งให้ทราบ พ.ศ. 2565** มีผลบังคับ 20 สิงหาคม 2566 สร้างหน้าที่ **แจ้งต่อ ETDA ก่อนเริ่มประกอบธุรกิจ** พร้อมหน้าที่ด้านความโปร่งใส (เปิดเผยเงื่อนไขบริการ ราคา/ค่าบริการ และปัจจัยสำคัญของอัลกอริทึมที่ใช้จัดอันดับหรือแนะนำ) และกลไกรับเรื่องร้องเรียน ([THNIC](https://www.thnic.or.th/act-digital2565/) · [ETDA — กฎหมาย/หลักเกณฑ์](https://www.etda.or.th/th/regulator/Digitalplatform/law.aspx)) **[ตีความ — เกณฑ์มาจากสื่อ ยังไม่ยืนยันจากตัวบท]** เกณฑ์ "แพลตฟอร์มทั่วไป" ที่สื่ออ้างคือรายได้ในไทยเกิน 1.8 ล้านบาท/ปี (บุคคลธรรมดา) หรือเกิน 50 ล้านบาท/ปี (นิติบุคคล) หรือผู้ใช้ในไทยเกิน 5,000 คน/เดือน ([กรุงเทพธุรกิจ](https://www.bangkokbiznews.com/tech/gadget/1094922)) — **เกณฑ์ผู้ใช้ 5,000 คน/เดือนคือเส้นที่แอปจองคอร์ทจะชนก่อนเกณฑ์รายได้มาก** และหน้าที่เปิดเผยเกณฑ์การจัดอันดับจะกระทบหน้า search/grid โดยตรง · **[ตัวบท]** ในทางกลับกัน **กฎหมาย e-Service VAT (พ.ร.บ.แก้ไขประมวลรัษฎากร ฉบับที่ 53 พ.ศ. 2564) ใช้กับผู้ให้บริการและแพลตฟอร์ม "ต่างประเทศ" เท่านั้น จึงไม่เกี่ยวกับ CourtPaka** ([Dharmniti](https://www.dharmniti.co.th/eservice-law/)) **[ตีความ]** แต่การที่ฝ่ายนิติบัญญัติต้องออกมาตรา 82/13 เป็นการเฉพาะเพื่อให้แพลตฟอร์มรับภาระภาษีแทนผู้ขาย เป็นสัญญาณว่าโดยหลักทั่วไป **แพลตฟอร์มไม่มีสิทธิหรือหน้าที่ทำแทนผู้ขายโดยอัตโนมัติ ต้องมีฐานกฎหมายเฉพาะ** — ซึ่งสอดคล้องกับข้อสรุปทั้งหมดในหัวข้อนี้

**PDPA** — **[ตัวบท]** มาตรา 40 กำหนดหน้าที่ผู้ประมวลผลข้อมูล (ดำเนินการเฉพาะตามคำสั่งของผู้ควบคุมข้อมูล · มีมาตรการความมั่นคงปลอดภัยและแจ้งเหตุละเมิด · จัดทำบันทึกรายการกิจกรรมการประมวลผล) และ **วรรคสามบังคับให้ผู้ควบคุมข้อมูลจัดให้มีข้อตกลงระหว่างกัน (DPA)** ([PDPA Thailand ม.40](https://pdpathailand.com/pdpa/content/article40.php)) **[ตีความ]** สำหรับข้อมูลผู้จองที่ใช้ออกเอกสารภาษี สนามคือผู้ควบคุมข้อมูล (ผู้มีหน้าที่ตามประมวลรัษฎากร) และแพลตฟอร์มคือผู้ประมวลผล ⇒ ต้องมี DPA ในข้อตกลงสนาม · แต่สำหรับข้อมูลบัญชีผู้ใช้ทั่วไป แพลตฟอร์มเป็นผู้ควบคุมข้อมูลเอง ⇒ **เป็นสองบทบาทบนข้อมูลชุดต่างกัน ต้องเขียนแยก ไม่ใช่เลือกอย่างใดอย่างหนึ่ง** · และหน้าที่เก็บเอกสารภาษีตามประมวลรัษฎากรเป็น **ฐานทางกฎหมาย** ที่ทำให้การเก็บข้อมูลผู้จองบางส่วนต่อหลังลบบัญชีชอบด้วย PDPA — แต่ **ใบกำกับภาษีเต็มรูปที่มีชื่อ-ที่อยู่ผู้ซื้อจะ anonymise ไม่ได้** เพราะจะทำให้เอกสารไม่ครบตามมาตรา 86/4 ⇒ ต้องเขียนใน privacy notice ว่าเก็บตามกฎหมายภาษีและไม่ลบตามคำขอ

### 2.4 ยกเลิกการจอง = ใบลดหนี้ · มัดจำ = สองใบต่อการจอง

**[ตัวบท]** มาตรา 86/10 ให้ออกใบลดหนี้เมื่อต้องคำนวณ VAT ใหม่เพราะมูลค่าลดลง "เพราะเหตุการณ์ตามที่ระบุไว้ในมาตรา 82/10" และต้องออก **ในเดือนภาษีที่เหตุการณ์เกิดขึ้น เว้นแต่มีเหตุจำเป็นไม่สามารถออกได้ทัน ก็ให้ออกในเดือนภาษีถัดไป** ([rd.go.th/5208.html](https://www.rd.go.th/5208.html) · ข้อความกำหนดเวลาเดียวกันใน [ป.80/2542](https://www.rd.go.th/3574.html)) โดย **ใบลดหนี้ให้ถือเป็นใบกำกับภาษี** ([Legardy](https://legardy.com/thai-law/revenue-code/revenue-code-vat-tax-invoices-section-86-14))

**[ตัวบท]** เหตุตามมาตรา 82/10 มีสี่อนุ โดยอนุที่เปิดทางกว้างที่สุดคือ (4) "มีการบอกเลิกสัญญาบริการเนื่องจากเหตุและตามเงื่อนไขที่อธิบดีกำหนด" ([rd.go.th/5206.html](https://www.rd.go.th/5206.html)) และ **ประกาศอธิบดีฯ VAT ฉบับที่ 82 ข้อ 2** แจกแจง "เหตุอื่น" หกข้อ ซึ่งสองข้อตรงกับการยกเลิกการจองแบบไม่ต้องตีความ: ข้อ 2(2) "เหตุเนื่องจากผู้ประกอบการจดทะเบียนได้มีการคืนเงินจ่ายล่วงหน้า **เงินประกัน เงินมัดจำ เงินจอง** หรือเงินอื่นที่เรียกเก็บในลักษณะทำนองเดียวกันให้แก่ผู้ซื้อสินค้าหรือผู้รับบริการตามข้อตกลงทางการค้า" และข้อ 2(6) "**เหตุเนื่องจากไม่มีการให้บริการตามสัญญา**" ([rd.go.th/3380.html](https://www.rd.go.th/3380.html))

**[ตัวบท]** รายการที่ใบลดหนี้ต้องมีเทียบได้กับใบเพิ่มหนี้ตามมาตรา 86/9 คือ คำว่า "ใบลดหนี้"/"ใบเพิ่มหนี้" ในที่เห็นได้เด่นชัด · ชื่อ ที่อยู่ เลขผู้เสียภาษีของผู้ออก (และของตัวแทนถ้ามี) · ชื่อและที่อยู่ของผู้ซื้อ · วันเดือนปี · **หมายเลขลำดับของใบกำกับภาษีเดิม** พร้อมมูลค่าเดิม มูลค่าที่ถูกต้อง ผลต่าง และจำนวนภาษีที่ลดลง · **คำอธิบายสั้น ๆ ถึงสาเหตุ** · และข้อความอื่นที่อธิบดีกำหนด ([rd.go.th/5208.html](https://www.rd.go.th/5208.html))

**[ตีความ]** สามกลไกที่กฎหมายมีแก้ปัญหาต่างกันคนละเรื่อง และการเลือกผิดคือการสร้างเอกสารที่ไม่มีฐาน: **ใบแทน** (มาตรา 86/12 + ประกาศฯ ฉบับที่ 36) ใช้เมื่อตัวเอกสารหาย ถูกทำลาย หรือชำรุด แต่ข้อมูลถูกต้อง — ทำโดยถ่ายสำเนาจากสำเนาฉบับเดิมแล้วบันทึก "ใบแทนออกให้ครั้งที่" วันที่ออก คำอธิบายย่อ และลายมือชื่อผู้ออก บันทึกรายการเดียวกันไว้ด้านหลังสำเนาฉบับเดิม และ **ลงการออกใบแทนในรายงานภาษีขายของเดือนที่ออกใบแทน** [ตัวบท] ([rd.go.th/3401.html](https://www.rd.go.th/3401.html)) · **ยกเลิกแล้วออกฉบับใหม่** (ป.86/2542 ข้อ 24–25) ใช้เมื่อ **ข้อมูลในเอกสารผิด** และบังคับให้ฉบับใหม่ลงวันเดียวกับฉบับเดิม [ตัวบท] ([rd.go.th/3568.html](https://www.rd.go.th/3568.html)) · **ใบลดหนี้** ใช้เมื่อเอกสารเดิมถูกต้อง ณ วันออก แต่ข้อเท็จจริงเปลี่ยนภายหลัง ⇒ **การยกเลิกการจองอยู่ในกลุ่มที่สาม** เพราะใบกำกับภาษีเดิมไม่ได้ผิด และเหตุเกิดคนละวันกับวันออกเอกสาร ซึ่งขัดกับเงื่อนไข "ลงวันเดิม" ของข้อ 25 โดยธรรมชาติ ⇒ **PRD บรรทัด "ยกเลิกเอกสารเดิม หรือออกใบลดหนี้ (รอคำตอบ Q1)" ควรตัดทางเลือกแรกออก**

**[ตีความ]** **ยอดในใบลดหนี้ควรเท่ากับยอดที่คืนจริง ไม่ใช่ราคาเต็ม** เพราะเหตุตามข้อ 2(2) พูดถึง "การคืนเงิน" และรายการตามมาตรา 86/9–86/10 ให้แสดง "มูลค่าที่ถูกต้อง" กับ "ผลต่าง" ⇒ กรณีคืน 50% มูลค่าที่ถูกต้องคือส่วนที่สนามเก็บไว้ **แต่ไม่พบตัวบทหรือข้อหารือที่พูดถึงการคืนบางส่วนของค่าบริการโดยตรง** (จะออกใบลดหนี้เต็มจำนวนแล้วออกใบกำกับภาษีใหม่สำหรับส่วนที่ริบ หรือออกใบลดหนี้เฉพาะส่วนต่าง — ยังไม่มีคำตอบ)

**[ตีความ]** **"เก็บเงินเพิ่มภายหลัง" ส่วนใหญ่ไม่ใช่ใบเพิ่มหนี้** เพราะเหตุตามมาตรา 82/9 ที่ปรากฏบนหน้า rd.go.th มีเพียงการเพิ่มราคาสินค้าที่ขายเกินจำนวนที่ตกลง และการเพิ่มราคาค่าบริการเนื่องจากให้บริการเกินกว่าข้อกำหนดที่ตกลงกัน [ตัวบท] ([rd.go.th/5206.html](https://www.rd.go.th/5206.html)) ⇒ ลูกค้าที่ตกลง **ซื้อชั่วโมงเพิ่มหน้าสนาม** เป็นการให้บริการรายการใหม่ที่มีราคาของตัวเอง ควรออกใบกำกับภาษีฉบับใหม่ · และ **การเก็บส่วนที่เหลือของมัดจำไม่ใช่ใบเพิ่มหนี้** เพราะราคาไม่ได้เพิ่ม แต่เป็นการรับชำระงวดที่สองของราคาเดิม

**tax point ของมัดจำ** — **[ตัวบท]** มาตรา 78/1(1) ระบุว่าความรับผิดในการเสีย VAT จากการให้บริการเกิด **เมื่อได้รับชำระราคาค่าบริการ** เว้นแต่ได้ออกใบกำกับภาษีหรือได้ใช้บริการก่อน ([rd.go.th/5205.html](https://www.rd.go.th/5205.html)) และ **คำสั่งกรมสรรพากรที่ ป.73/2541** ครอบ "เงินจ่ายล่วงหน้า เงินประกัน เงินมัดจำ เงินจอง หรือเงินอื่นที่เรียกเก็บในลักษณะทำนองเดียวกัน" โดยสำหรับผู้ให้บริการที่เรียกเก็บเงินดังกล่าว "**ความรับผิดในการเสียภาษีมูลค่าเพิ่มจากการให้บริการเกิดขึ้นในขณะได้รับชำระเงินดังกล่าว**" ([rd.go.th/3580.html](https://www.rd.go.th/3580.html)) โดยมีข้อยกเว้นเฉพาะเรื่อง เช่น เงินมัดจำภาชนะบรรจุที่คืนให้โดยไม่มีเงื่อนไข และเงินประกันการเช่าที่อยู่อาศัยตามเงื่อนไข

**[ตีความ]** ⇒ มัดจำที่รับตอนจองเป็นการรับชำระราคาค่าบริการบางส่วน ต้องออกใบกำกับภาษีสำหรับยอดนั้นในวันที่รับเงิน และเมื่อเก็บส่วนที่เหลือหน้าสนามก็ออกอีกฉบับ ⇒ **ปกติได้สองใบต่อการจองหนึ่งรายการ** ซึ่งสอดคล้องกับวรรคของมาตรา 105 ที่สั่งให้ออกใบรับทุกงวด

**[ความขัดแย้งของแหล่ง]** สำนักงานบัญชีบางแห่งอ่านไปทางตรงข้ามว่าเงินมัดจำที่รับไว้เป็นหลักประกันลงบัญชีเป็นหนี้สิน ไม่ใช่รายได้ จึงยังไม่ต้องออกใบกำกับภาษีตอนรับ ออกเพียงใบเสร็จรับเงิน และ VAT เกิดเมื่อส่งมอบบริการ ([FlowAccount](https://flowaccount.com/blog/accounting-and-tax-for-deposit/)) — **ขัดกับ ป.73/2541 ในบริบทการให้บริการ** **[ตีความ]** คำอธิบายที่ประนีประนอมได้คือมัดจำที่ *เป็นหลักประกันและต้องคืนโดยไม่มีเงื่อนไข* ต่างจากมัดจำที่ *เป็นส่วนของราคาค่าบริการ* ซึ่งการจองคอร์ทเป็นอย่างหลัง — แต่นี่เป็นการตีความ ต้องยืนยันด้วยข้อหารือที่ตรงกรณี

### 2.5 รายงานภาษีขาย: เจ็ดคอลัมน์ที่มาจากแบบแนบท้ายของกรมสรรพากรเอง

**[ตัวบท]** มาตรา 87 บังคับผู้ประกอบการจดทะเบียนให้จัดทำ **รายงานภาษีขาย** และ **รายงานภาษีซื้อ** ส่วน **รายงานสินค้าและวัตถุดิบบังคับเฉพาะผู้ประกอบการจดทะเบียนที่ประกอบกิจการขายสินค้า** ([สถาบันนิติธรรมาลัย ม.87–87/3](https://www.drthawip.com/taxlaw/029) · [rd.go.th/5209.html](https://www.rd.go.th/5209.html)) ตัวบทไม่ได้ลิสต์คอลัมน์ไว้ในมาตรา — **ประกาศอธิบดีฯ VAT ฉบับที่ 89 ลงวันที่ 29 เมษายน 2542 ข้อ 2** สั่งว่ารายงานต้องมี "รายการและข้อความ **อย่างน้อย** ตามแบบที่แนบท้ายประกาศนี้" ([rd.go.th/3374.html](https://www.rd.go.th/3374.html)) และถูกแก้โดยประกาศฯ ฉบับที่ 197/202 ให้เพิ่มเลขผู้เสียภาษีของคู่ค้าและข้อมูลสถานประกอบการ โดยเลื่อนวันเริ่มใช้เป็น **1 มกราคม 2558** ([rd.go.th/27985.html](https://www.rd.go.th/27985.html))

**[ตัวบท]** คอลัมน์ในแบบแนบท้าย ดึงจากไฟล์ของกรมสรรพากรโดยตรง ([197a.doc](https://www.rd.go.th/fileadmin/user_upload/kormor/197a.doc) · รุ่นแนบท้ายฉบับ 202 ที่ [vat-202-01.pdf](https://www.rd.go.th/fileadmin/images/image_law/images/vat-202-01.pdf)) — หัวรายงานมีสามฟิลด์: "เดือนภาษี … ปี …" · "ชื่อผู้ประกอบการ … เลขประจำตัวผู้เสียภาษีอากร …" · "ชื่อสถานประกอบการ … ☐ สำนักงานใหญ่ ☐ สาขาที่ …" และตารางมีเจ็ดคอลัมน์:

| # | คอลัมน์ตามแบบ |
|---|---|
| 1 | ใบกำกับภาษี → วัน เดือน ปี |
| 2 | ใบกำกับภาษี → เล่มที่ / เลขที่ |
| 3 | ชื่อผู้ซื้อสินค้า/ผู้รับบริการ |
| 4 | เลขประจำตัวผู้เสียภาษีอากรของผู้ซื้อสินค้า/ผู้รับบริการ |
| 5 | สถานประกอบการ → ช่องย่อย "สำนักงานใหญ่" และ "สาขาที่" |
| 6 | มูลค่าสินค้าหรือบริการ |
| 7 | จำนวนเงินภาษีมูลค่าเพิ่ม |
| — | แถวท้าย **รวม** |

**[ตัวบท]** หมายเหตุท้ายแบบเป็นกฎการกรอกที่ซอฟต์แวร์ต้องรองรับ และมีข้อหนึ่งที่สำคัญกับ CourtPaka มาก: กรณีไม่สามารถกรอกชื่อผู้ซื้อได้ "**การลงรายการโดยใช้หลักฐานรายงานสรุปการขายประจำวัน ให้กรอก 'รายงานสรุปการขายประจำวัน'** … **กรณีอื่น ๆ เช่น ใบกำกับภาษีอย่างย่อ ให้กรอก 'ขายสินค้าหรือให้บริการ'**" · อีกข้อระบุว่าช่องเลขผู้เสียภาษีและช่องสถานประกอบการให้กรอกตามที่ปรากฏใน **ใบกำกับภาษีตามมาตรา 86/4 ใบเพิ่มหนี้ตามมาตรา 86/9 หรือใบลดหนี้ตามมาตรา 86/10** และช่องสถานประกอบการมีความหมายเฉพาะกรณีผู้ซื้อ **เป็นผู้ประกอบการจดทะเบียน VAT** ([197a.doc](https://www.rd.go.th/fileadmin/user_upload/kormor/197a.doc)) · อีกข้ออนุญาตให้ "**เพิ่มช่องอีกหนึ่งช่องก็ได้**" สำหรับเลขรหัสเครื่องบันทึกการเก็บเงิน

**[ตีความ]** สามข้อที่ตามมา: สนามแบดมินตันที่เป็นกิจการบริการล้วน **ไม่ต้องทำรายงานสินค้าและวัตถุดิบ** — แต่ถ้าขายลูกแบด น้ำดื่ม หรือบริการขึ้นเอ็น ก็เข้าข่าย "ขายสินค้า" สำหรับส่วนนั้น · คำว่า "อย่างน้อย" แปลว่า **เพิ่มคอลัมน์ได้ ตัดไม่ได้** · และหัวรายงานที่มี "เดือนภาษี" + "สำนักงานใหญ่/สาขาที่" แปลว่ารายงานเป็น **รายเดือนภาษีต่อสถานประกอบการหนึ่งใบ** ไม่ใช่รวมทุกสาขา ⇒ export ต้องแยกตามสถานประกอบการ

**[ตัวบท]** กำหนดเวลาลงรายการอยู่ในตัวบทมาตรา 87 เอง ไม่ใช่แค่แนวปฏิบัติ: "การลงรายการให้ลงภายใน **สามวันทำการ** นับแต่วันที่ได้มาหรือจำหน่ายออกไป ทั้งนี้ เว้นแต่ในกรณีจำเป็น อธิบดีจะกำหนดเป็นอย่างอื่นตามที่เห็นสมควร" ([สถาบันนิติธรรมาลัย](https://www.drthawip.com/taxlaw/029) · ข้อความเดียวกันที่ [rd.go.th/5209.html](https://www.rd.go.th/5209.html)) **[ตีความ]** ถ้าระบบเขียนแถวรายงานใน transaction เดียวกับการออกเอกสาร ก็ผ่านโดยอัตโนมัติ — เงื่อนไขที่อันตรายคือการ "ทำรายงานย้อนหลังตอนสิ้นเดือน" จากไฟล์ดิบ

**[ตัวบท]** ระยะเวลาเก็บเอกสารมาจากสองกฎหมายที่นับเวลาเริ่มไม่เหมือนกัน: **มาตรา 87/3** ให้เก็บรายงาน ใบกำกับภาษี และเอกสารประกอบ **ณ สถานประกอบการ ไม่น้อยกว่าห้าปี** โดยอธิบดีกำหนดให้เก็บนานกว่าได้แต่ไม่เกินเจ็ดปี และกรณีเลิกประกอบกิจการให้เก็บต่อไปอีกสองปี ([สถาบันนิติธรรมาลัย ม.87/3](https://www.drthawip.com/taxlaw/029) · [rd.go.th/5209.html](https://www.rd.go.th/5209.html)) ส่วน **พ.ร.บ.การบัญชี พ.ศ. 2543 มาตรา 14** ให้เก็บ **ไม่น้อยกว่าห้าปีนับแต่วันปิดบัญชี** ขยายได้ไม่เกินเจ็ดปี ([DBD](https://www.dbd.go.th/law/410)) **[ตีความ]** แนวปลอดภัยคือ **เก็บเจ็ดปีนับจากวันยื่นแบบของเดือนภาษีนั้น** ซึ่งครอบทั้งสองฉบับ · และคำว่า "ณ สถานประกอบการ" ในมาตรา 87/3 ทำให้การเก็บบนคลาวด์เพียงที่เดียวเป็นประเด็น ⇒ ต้องมีความสามารถดึงมาแสดงหรือพิมพ์ที่สถานประกอบการได้ทันทีเมื่อเจ้าพนักงานขอ

**[ตัวบท]** การยื่น ภ.พ.30 ภายในวันที่ 15 ของเดือนถัดไป ยื่นผ่าน e-Filing ได้ **ขยายอีก 8 วัน → วันที่ 23** ([efiling.rd.go.th](https://efiling.rd.go.th/rd-cms/extend) · [ประกาศกระทรวงการคลังเรื่องการขยายกำหนดเวลา](https://www.rd.go.th/46202.html)) โดยผู้ยื่นภายในกำหนดที่ขยายแล้วไม่ต้องรับผิดเบี้ยปรับและเงินเพิ่ม ส่วนยื่นเกินกำหนดเสียเบี้ยปรับตามมาตรา 89 และ **เงินเพิ่มร้อยละ 1.5 ต่อเดือน** ตามมาตรา 89/1 ([efiling — ถาม-ตอบ](https://efiling.rd.go.th/rd-cms/ask) · [rd.go.th/5209.html](https://www.rd.go.th/5209.html)) **[ตีความ — จากแหล่งทุติยภูมิ]** ช่วงเวลาที่มาตรการขยาย 8 วันมีผลคือ 1 กุมภาพันธ์ 2567 – **31 มกราคม 2570** ([Tax-EZ](https://tax-ez.info/Update/View/pD7xi0Ug/)) ⇒ **วันที่ 23 ต้องเป็น config ไม่ใช่ hard-code**

**e-Tax Invoice** — **[ตีความ — ทุกตัวเลขในย่อหน้านี้มาจากแหล่งทุติยภูมิ]** มีสองระบบ: **by Email / by Time Stamp** สำหรับผู้มีรายได้ไม่เกิน 30 ล้านบาท ใช้ PDF/A-3 + ประทับรับรองเวลา ไม่ต้องมีใบรับรองอิเล็กทรอนิกส์ และไม่มีค่าใช้จ่าย โดยวิธีใช้คือส่งอีเมลให้ลูกค้าและ CC ไปที่ระบบกลาง · และ **ระบบเต็ม (e-Tax Invoice & e-Receipt)** ใช้ XML ลงลายมือชื่อดิจิทัล ต้องมีใบรับรองจาก CA ไม่จำกัดรายได้ ยื่นคำขอด้วยแบบ ก.อ.01 และนำส่งได้สามทาง ([PEAK](https://www.peakaccount.com/blog/tax/gen-tax/tax-difference-of-etax) · [FlowAccount](https://flowaccount.com/blog/e-tax-invoice-by-time-stamp-electronic-invoice/)) โดยเอกสารอิเล็กทรอนิกส์ที่ทำได้ครอบห้าประเภทตามมาตรา 86/4, 86/6, 86/9, 86/10 และ 105 ทวิ **[ตีความ]** กระบวนการ "CC อีเมลทีละใบ" ไม่เหมาะกับสนามที่ออกเอกสารวันละหลายสิบใบ ⇒ ถ้าจะไป e-Tax จริงควรไประบบเต็ม · และเงื่อนไข "ต้องไม่อยู่ระหว่างขออีกระบบ" แปลว่าเลือกได้ระบบเดียวในเวลาเดียว การย้ายต้องวางแผน

### 2.6 ค่าคอมมิชชัน: ฐาน VAT คือค่าคอมมิชชันเท่านั้น ส่วนหัก ณ ที่จ่ายขึ้นกับรูปนิติบุคคลของทั้งสองฝ่าย

**[ตัวบท]** "บริการ" ตามมาตรา 77/1(10) หมายถึงการกระทำใด ๆ อันอาจหาประโยชน์อันมีมูลค่าซึ่งมิใช่การขายสินค้า และมาตรา 77/2(1) ให้การให้บริการในราชอาณาจักรอยู่ในบังคับ VAT · **มาตรา 79 กำหนดฐานภาษีเป็น "มูลค่าทั้งหมดที่ผู้ประกอบการได้รับหรือพึงได้รับจากการขายสินค้าหรือการให้บริการ"** ([rd.go.th/5205.html](https://www.rd.go.th/5205.html)) **[ตัวบท/แนววินิจฉัย]** ข้อหารือ **กค 0702/4911 (22 มิถุนายน 2552)** เรื่องการออกใบกำกับภาษีสำหรับรายได้ค่านายหน้า วินิจฉัยว่านายหน้ามีหน้าที่จัดทำใบกำกับภาษีและเรียกเก็บ VAT จากคู่สัญญา และฝ่ายที่จ่ายนำภาษีซื้อนั้นไปหักจากภาษีขายได้ ([rd.go.th/41445.html](https://www.rd.go.th/41445.html))

**[ตีความ]** ⇒ **ฐานภาษีของแพลตฟอร์มคือค่าคอมมิชชันของตัวเองเท่านั้น ไม่ใช่ยอดค่าสนามทั้งก้อน** เพราะสนามให้บริการแก่ผู้เล่น แพลตฟอร์มให้บริการแก่สนาม เป็นสองรายการต่างคู่สัญญา และในโมเดลที่ผู้เล่นโอนตรงเข้าพร้อมเพย์ของสนาม เงินค่าคอร์ทไม่เคยเป็น "มูลค่าที่แพลตฟอร์มได้รับหรือพึงได้รับ" เลย · ความเสี่ยงจึงอยู่ที่ **รูปแบบสัญญาและเอกสาร ไม่ใช่กระแสเงิน** — ถ้าแพลตฟอร์มเริ่มกำหนดราคาเองหรือออกใบเสร็จค่าคอร์ทในนามตัวเอง ก็เสี่ยงถูกมองเป็นผู้ให้บริการเอง (principal) แล้วฐานภาษีกลายเป็นยอดเต็ม **ไม่พบเกณฑ์เส้นแบ่งที่เป็นทางการระหว่างสองสถานะนี้สำหรับแพลตฟอร์ม**

**[ตัวบท]** ถ้าแพลตฟอร์มยังไม่จด VAT ก็ออกใบกำกับภาษีไม่ได้เช่นเดียวกับสนาม (มาตรา 86/13) ให้ออกใบแจ้งหนี้ + ใบเสร็จรับเงินโดยไม่มีบรรทัด VAT **[ตีความ]** และ **ห้ามใส่ช่องเลขผู้เสียภาษีพร้อมคำว่า "ใบกำกับภาษี" ไว้เผื่ออนาคต** เพราะเสี่ยงถูกถือว่าออกใบกำกับภาษีโดยไม่มีสิทธิ

**[ตัวบท]** ลำดับเอกสารถูกกำหนดโดย tax point: มาตรา 78/1(1) ให้ความรับผิดเกิดเมื่อได้รับชำระราคาค่าบริการ เว้นแต่ได้ออกใบกำกับภาษีหรือได้ใช้บริการก่อน ([rd.go.th/5205.html](https://www.rd.go.th/5205.html) · [สถาบันนิติธรรมาลัย ม.78–78/3](https://www.drthawip.com/taxlaw/020)) และใบกำกับภาษีที่มีข้อความแสดงว่าได้รับชำระราคาแล้วถือเป็นใบรับตามมาตรา 105 วรรคสามได้ ([มาตรา 105](https://deka.in.th/laws/rvc/105)) **[ตีความ]** ⇒ ลำดับที่ถูกคือ **ใบแจ้งหนี้ (วางบิล) → ได้รับชำระ → ออกใบกำกับภาษีในวันที่ได้รับชำระ** และ **ห้ามออกใบกำกับภาษีพร้อมใบแจ้งหนี้** ซึ่งเป็นสิ่งที่ระบบบัญชีสำเร็จรูปหลายตัวทำโดยดีฟอลต์ — ถ้าทำ แพลตฟอร์มต้องนำส่ง VAT ของบิลที่ยังไม่เก็บเงินได้ทุกเดือน ⇒ **"วันที่ได้รับชำระ" ต้องเป็นฟิลด์ที่บันทึกแยกจาก "วันที่ออกบิล" ไม่ใช่อนุมานจากกัน**

**[ตัวบท]** อัตราหัก ณ ที่จ่าย: **ท.ป. 4/2528 ข้อ 3/1** กำหนดว่านิติบุคคลผู้จ่ายเงินได้ตามมาตรา 40(2) ให้ผู้รับซึ่งเป็น **บริษัทหรือห้างหุ้นส่วนนิติบุคคลที่ประกอบกิจการในประเทศไทย** ต้องหักในอัตรา **3.0%** (มูลนิธิ/สมาคม 10%) ([rd.go.th/3479.html](https://www.rd.go.th/3479.html) · [วิกิซอร์ซ ท.ป. 4/2528](https://th.wikisource.org/wiki/%E0%B8%84%E0%B8%B3%E0%B8%AA%E0%B8%B1%E0%B9%88%E0%B8%87%E0%B8%81%E0%B8%A3%E0%B8%A1%E0%B8%AA%E0%B8%A3%E0%B8%A3%E0%B8%9E%E0%B8%B2%E0%B8%81%E0%B8%A3%E0%B8%97%E0%B8%B5%E0%B9%88_%E0%B8%97.%E0%B8%9B._4/2528)) และ **ข้อ 12/1** (ค่าบริการอื่น ๆ) อัตรา **3%** ทั้งผู้รับที่เป็นบุคคลธรรมดาและนิติบุคคลไทย ([วิกิซอร์ซ](https://th.wikisource.org/wiki/%E0%B8%84%E0%B8%B3%E0%B8%AA%E0%B8%B1%E0%B9%88%E0%B8%87%E0%B8%81%E0%B8%A3%E0%B8%A1%E0%B8%AA%E0%B8%A3%E0%B8%A3%E0%B8%9E%E0%B8%B2%E0%B8%81%E0%B8%A3%E0%B8%97%E0%B8%B5%E0%B9%88_%E0%B8%97.%E0%B8%9B._4/2528)) · ทุกข้อที่เกี่ยวข้องระบุ **ผู้มีหน้าที่หักเป็น "บริษัทหรือห้างหุ้นส่วนนิติบุคคล หรือนิติบุคคลอื่น"** และแบบยื่นคือ ภ.ง.ด.3 (ผู้รับบุคคลธรรมดา) / ภ.ง.ด.53 (ผู้รับนิติบุคคล) ภายใน 7 วันนับแต่วันสิ้นเดือนของเดือนที่จ่าย ([rd.go.th/3535.html](https://www.rd.go.th/3535.html)) **[ตีความ]** ⇒ **ถ้าแพลตฟอร์มเป็นบริษัท คำตอบคือ 3% ไม่ว่าจะตีความรายการเป็นค่านายหน้า 40(2) หรือค่าบริการตามข้อ 12/1** จึงเป็นเหตุที่คำถาม "40(2) หรือ 40(8)" ไม่กระทบยอดเงินในกรณีนี้ · และ **ผู้จ่ายที่เป็นบุคคลธรรมดาไม่มีหน้าที่หัก** ตามถ้อยคำของ ท.ป. 4/2528 ⇒ ยอดที่แพลตฟอร์มได้รับจริงต่างกันตามรูปนิติบุคคลของสนาม

**[ตัวบท]** ฝั่งภาษีเงินได้ของแพลตฟอร์มเองมีข้อที่ตัดสินโครงสร้างธุรกิจได้: เงินได้ตามมาตรา 40(2) ซึ่งรวม **ค่านายหน้า** **หักค่าใช้จ่ายเหมาได้ 50% แต่ไม่เกิน 100,000 บาท** ([PEAK](https://www.peakaccount.com/blog/tax/corporate-income-tax/income-tax) · [iTAX pedia เงินได้ประเภทที่ 2](https://www.itax.in.th/pedia/%E0%B9%80%E0%B8%87%E0%B8%B4%E0%B8%99%E0%B9%84%E0%B8%94%E0%B9%89%E0%B8%9B%E0%B8%A3%E0%B8%B0%E0%B9%80%E0%B8%A0%E0%B8%97%E0%B8%97%E0%B8%B5%E0%B9%88-2/)) **[ตีความ]** ⇒ เพดาน 100,000 บาทนี้บีบทันทีเมื่อค่าคอมมิชชันโตเกินราว 200,000 บาท/ปี เพราะค่า server ค่าพัฒนา และค่าธรรมเนียมชำระเงินส่วนที่เกินไม่ได้รับรู้เลย ในขณะที่บริษัทหักตามจริงและมีผลขาดทุนยกไปได้ — **การเรียกชื่อรายการว่า "ค่านายหน้า" ในสัญญาและใบแจ้งหนี้จึงเป็นการตัดสินใจทางภาษี ไม่ใช่เรื่องถ้อยคำ**

**netting** — **[ตีความ]** ในทางภาษี การหักค่าคอมมิชชันจากยอดที่จะโอนให้สนาม **ไม่ลดฐาน VAT และไม่ลดยอดที่ต้องหัก ณ ที่จ่าย** วันหักกลบคือวันที่ได้รับชำระตามมาตรา 78/1(1) ⇒ VAT ถึงกำหนดเร็วกว่าการวางบิลแล้วรอเก็บ แต่กำจัดความเสี่ยงหนี้สูญ · **ในโมเดลปัจจุบัน netting ทำไม่ได้อยู่แล้ว** เพราะเงินไม่ผ่านแพลตฟอร์ม ⇒ **US-21 เป็นการเรียกเก็บทีหลังโดยบังคับ** และแพลตฟอร์มแบกความเสี่ยงหนี้สูญ ⇒ ต้องมีสถานะ "ค้างชำระ/เกินกำหนด" ของใบแจ้งหนี้ค่าคอมมิชชันในระบบ · และถ้าจะเปลี่ยนไปรับเงินผ่านบัญชีกลาง จะเปิดทั้งประเด็นฐานภาษีอาจถูกมองเป็นยอดเต็ม และกฎเกณฑ์การเป็นผู้ให้บริการชำระเงินของ ธปท. ซึ่งอยู่นอกขอบเขตงานนี้

## 3. สิ่งที่ยืนยันไม่ได้ และต้องถามนักบัญชีหรือกรมสรรพากร

ส่วนนี้ไม่ใช่ส่วนท้าย แต่เป็นส่วนที่มีมูลค่าที่สุดของรายงาน เพราะทุกบรรทัดคือที่ที่การเขียนโค้ดจากความเข้าใจผิดจะแพงที่สุด

### 3.1 สามคำถามที่ควรยื่นข้อหารือกรมสรรพากร

งานวิจัยรอบนี้ค้นแล้วไม่พบคำตอบที่เผยแพร่สำหรับสามข้อนี้ และทั้งสามข้ออยู่ก่อนการเขียนฟีเจอร์

1. **แพลตฟอร์มที่ไม่ได้รับชำระเงินแทนสนาม จะออกใบกำกับภาษีในนามสนามตามมาตรา 86 วรรคสี่ ได้หรือไม่** — ประกาศฯ ฉบับที่ 68 ผูกกับการ "รับชำระเงินแทน" ซึ่ง CourtPaka ไม่ทำ ส่วนประกาศฯ ฉบับที่ 8 เขียนไว้สำหรับสินค้า ⇒ ไม่มีหลักเกณฑ์ที่เขียนถึงกรณีนี้
2. **การที่สนามเป็นผู้ออกเอกสาร แต่เอกสารถูกสร้างและเก็บในระบบของแพลตฟอร์ม ถือว่าสนาม "ออก" เองครบถ้วนหรือไม่** — ไม่พบหนังสือหรือข้อหารือที่ยืนยันว่าผู้ให้บริการซอฟต์แวร์ไม่ถือเป็นตัวแทนตามมาตรา 86 วรรคสี่ ข้อสรุปในรายงานนี้เป็นการอนุมานจากโครงของตัวบทเท่านั้น
3. **เลขที่และเล่มที่ต้องเดินอย่างไรกรณีระบบกลางออกเอกสารให้สนามหลายราย** — ป.86/2542 ข้อ 5 ใช้คำว่า "แบบพิมพ์ใบกำกับภาษีของตัวแทน" ซึ่งชี้ไปทางเลขชุดของตัวแทน ตรงข้ามกับสถาปัตยกรรมที่เก็บข้อมูลผู้ประกอบการรายสนามไว้เพื่อพิมพ์ในนามสนาม

**คำถามที่ควรยื่นเพิ่มถ้ายื่นได้มากกว่าสามข้อ** — สนามกีฬารายชั่วโมงเข้าข่ายกิจการค้าปลีกตามประกาศฯ ฉบับที่ 32 และมีสิทธิออกใบกำกับภาษีอย่างย่อหรือไม่ · การริบมัดจำเพราะ no-show ยังอยู่ในฐาน VAT หรือไม่ · และการคืนค่าบริการบางส่วนตามนโยบายยกเลิกต้องออกใบลดหนี้เฉพาะส่วนต่าง หรือออกเต็มจำนวนแล้วออกใบกำกับภาษีใหม่สำหรับส่วนที่ริบ

### 3.2 สามเรื่องที่แหล่งขัดกันเอง — และทั้งสองฝั่งมีฐาน

**(ก) คอร์ทรายชั่วโมงเป็น "ค่าเช่า" หรือ "ค่าบริการ"** นี่คือคำถามที่อยู่ก่อนทุกอย่างในรายงานนี้ เพราะมันตัดสินทั้งว่าต้องเสีย VAT ไหม และหัก ณ ที่จ่ายเท่าไร

- **อ่านว่าเป็นบริการ** — **[ตัวบท]** ป.90/2542 วางเส้นแบ่งว่าการให้ **เช่า** คือ "ผู้ให้เช่าต้องส่งมอบการครอบครองพื้นที่อสังหาริมทรัพย์ให้แก่ผู้เช่า" ส่วนการให้ **บริการ** คือ "ผู้ประกอบการไม่ได้ส่งมอบการครอบครองพื้นที่ … ให้แก่ผู้ใช้พื้นที่" และถ้าผู้ประกอบการยังคุมพื้นที่และจัดสิ่งอำนวยความสะดวก/พนักงานให้ ถือเป็นการให้บริการตามมาตรา 77/1(10) ในบังคับ VAT ([rd.go.th/3565.html](https://www.rd.go.th/3565.html)) ⇒ **[ตีความ]** สนามยังคุมไฟ อุปกรณ์ พนักงาน และกฎการใช้ ⇒ มีน้ำหนักไปทางบริการ ⇒ VAT + หัก ณ ที่จ่าย **3%**
- **อ่านว่าเป็นค่าเช่า** — **[ตัวบท]** การให้เช่าอสังหาริมทรัพย์แท้ ๆ ได้รับยกเว้น VAT ตามมาตรา 81 ([rd.go.th/3565.html](https://www.rd.go.th/3565.html)) และอัตราหักค่าเช่าทรัพย์สินคือ **5%** ทั้งกรณีผู้รับเป็นบุคคลธรรมดาและนิติบุคคลไทย ([rd.go.th/3535.html](https://www.rd.go.th/3535.html)) · **[ตีความ]** สำนักงานกฎหมายและสำนักงานบัญชีอธิบายหลักเดียวกันว่าถ้าต้องมอบทรัพย์สินให้ผู้เช่าและผู้เช่ารับผิดชอบการซ่อมแซมระหว่างเช่า รายได้นั้นเป็นค่าเช่า หัก 5% ([ธรรมนิติ](https://www.dharmniti.co.th/ความต่างของ-ค่าเช่ากับค่าบริการ/) · [BMU](https://bmu.co.th/withholding-tax-of-rental-expense/))
- **ไม่มีข้อหารือที่พูดถึงสนามแบดมินตันหรือสนามกีฬาโดยตรง** ข้อหารือที่ใกล้ที่สุดที่ปรากฏในผลค้นคือกรณีสนามกอล์ฟ ซึ่ง **ยังไม่ได้อ่านเนื้อหา** ([rd.go.th/23421.html](https://www.rd.go.th/23421.html) · [rd.go.th/25221.html](https://www.rd.go.th/25221.html) · [rd.go.th/43021.html](https://www.rd.go.th/43021.html)) — **นี่คือสิ่งแรกที่ควรทำในรอบวิจัยถัดไป** และแม้แต่ตัวอักษรของอนุมาตราที่ยกเว้น VAT ก็ยังไม่ยืนยัน (แหล่งหนึ่งอ้าง 81(1)(ต) อีกแหล่งอ้าง 81(1)(ณ))
- **[ตีความ]** ความเข้าใจผิดที่แพงที่สุดในเรื่องนี้คือสนามที่คิดว่าตัวเอง "ให้เช่า" จึงคิดว่าไม่ต้องสนใจเกณฑ์ 1.8 ล้าน

**(ข) ริบมัดจำจาก no-show เสีย VAT หรือไม่** สองการตีความขัดกันและทั้งคู่มีฐาน

- **อ่านว่า VAT คงอยู่** — มัดจำเป็นการรับชำระค่าบริการ VAT เกิดแล้วตามมาตรา 78/1(1) + ป.73/2541 ⇒ ไม่มีการคืนเงิน จึงไม่มีเหตุตามมาตรา 82/10 หรือประกาศฯ 82 ให้ออกใบลดหนี้ ⇒ VAT ที่เรียกเก็บไว้คงเดิม ไม่ต้องทำเอกสารเพิ่มเมื่อ no-show · ฐานที่แข็งของฝั่งนี้คือ **ประกาศฯ 82 ข้อ 2(2) ให้เหตุ "คืนเงิน" ไม่ใช่เหตุ "ไม่ได้ให้บริการแต่เก็บเงินไว้"** ([rd.go.th/3380.html](https://www.rd.go.th/3380.html))
- **อ่านว่าแปลงสภาพเป็นค่าเสียหาย** — เมื่อไม่มีการให้บริการเลย เงินที่ริบมีลักษณะเป็นค่าเสียหาย/เบี้ยปรับ ซึ่งตามหลักที่แหล่งทุติยภูมิอ้าง (ข้อหารือ กค 0706/3551) ไม่ใช่ค่าตอบแทนจากบริการ ⇒ ต้องออกใบลดหนี้ตามข้อ 2(6) ("ไม่มีการให้บริการตามสัญญา") แล้วถือเงินนั้นเป็นรายได้ที่ไม่มี VAT · ช่องที่เปิดให้ฝั่งนี้คือ **ข้อ 2(6) ไม่มีเงื่อนไขว่าต้องคืนเงินหรือไม่**
- ข้อหารือที่ใกล้ที่สุดที่เปิดอ่านได้ **อยู่ในระบบภาษีธุรกิจเฉพาะ ไม่ใช่ VAT**: กรณีริบเงินมัดจำ 15 ล้านบาทจากสัญญาจะซื้อจะขายที่ดิน กรมสรรพากรตอบว่าเงินมัดจำที่ริบเป็น "รายรับ" ตามมาตรา 91/1(1) ต้องเสียภาษีธุรกิจเฉพาะ ([rd.go.th/24177.html](https://www.rd.go.th/24177.html)) — ใช้เทียบเคียงได้อย่างระมัดระวังเท่านั้น
- **ไม่พบข้อหารือ VAT ที่ตรงกรณี "ริบเงินมัดจำค่าบริการเพราะลูกค้าไม่มาใช้บริการ"** และบทความที่อ้างข้อหารือ กค 0706/3551 **เปิดไม่ได้ (DNS ล้มเหลว)** ⇒ เลขข้อหารือนั้นยังไม่ได้ยืนยันจากแหล่งชั้นต้น

**(ค) หัก ณ ที่จ่ายเมื่อผู้รับเป็นบุคคลธรรมดา** แนวปฏิบัติในตลาดขัดกันเอง

- สายหนึ่งระบุว่าค่านายหน้าที่จ่ายให้บุคคลธรรมดาต้องหักตาม **อัตราก้าวหน้า (0–35%)** ตามมาตรา 50(1) ไม่ใช่ 3% ([IFS Cap Thai](https://www.ifscapthai.com/commission-withholding-tax-guide/))
- อีกสายหนึ่งสรุปว่าค่าคอมมิชชันหัก **3%** เหมือนกันทั้งบุคคลธรรมดาและนิติบุคคล ([SMEMove](https://smemove.com/blog/%E0%B8%84%E0%B9%88%E0%B8%B2%E0%B8%84%E0%B8%AD%E0%B8%A1%E0%B8%A1%E0%B8%B4%E0%B8%8A%E0%B8%8A%E0%B8%B1%E0%B9%88%E0%B8%99-%E0%B8%AB%E0%B8%B1%E0%B8%81%E0%B8%A0%E0%B8%B2%E0%B8%A9%E0%B8%B5-%E0%B8%93/))
- **[ตัวบท]** ท.ป. 4/2528 ข้อ 3/1 พูดถึงผู้รับที่เป็นนิติบุคคล/มูลนิธิสมาคมเท่านั้น จึงไม่ครอบคลุมผู้รับที่เป็นบุคคลธรรมดา ⇒ ทางเลือกกลายเป็น (ก) เรียกเป็นค่านายหน้า 40(2) → หักตามมาตรา 50(1) อัตราก้าวหน้า ซึ่งแกว่งตามข้อมูลรายปีที่ผู้จ่ายไม่มี = ในทางปฏิบัติแทบใช้ไม่ได้ หรือ (ข) เรียกเป็นค่าบริการตามข้อ 12/1 → หัก 3% คงที่
- ผลพ่วงที่ต่างกันด้วยคือ **กำหนดเวลาออก 50 ทวิ**: ถ้าเป็น "รายได้อื่น ๆ" ต้องออกทันทีเมื่อหัก ถ้าตีความเป็น 40(2) ที่หักตามมาตรา 50(1) อาจกลายเป็นภายใน 15 กุมภาพันธ์ของปีถัดไป ([iTAX pedia — ใบ 50 ทวิ](https://www.itax.in.th/pedia/%E0%B9%83%E0%B8%9A-50-%E0%B8%97%E0%B8%A7%E0%B8%B4/))
- **[ยังไม่ยืนยัน]** ไม่ได้ตัวบทมาตรา 50 และ 50 ทวิ verbatim เพราะ PDF คู่มือของกรมสรรพากรสามไฟล์ที่ลองอ่านเป็น binary ที่แปลงเป็นข้อความไม่ได้ ⇒ ยังไม่ยืนยันได้ว่าผู้จ่ายที่เป็นบุคคลธรรมดามีหน้าที่หักตามมาตรา 50(1) หรือไม่ (ถ้อยคำที่เล่าต่อกันมาเริ่มด้วย "ให้บุคคล ห้างหุ้นส่วน บริษัท…" ซึ่งถ้าจริงจะขัดกับคำสรุปของสำนักงานบัญชีที่ว่าบุคคลธรรมดาไม่ต้องหัก)

ข้อขัดกันข้อที่สี่ที่เล็กกว่าแต่กระทบเอกสารโดยตรงคือ **tax point ของมัดจำ** (ป.73/2541 ว่า VAT เกิดตอนรับเงิน vs สำนักงานบัญชีว่ามัดจำเป็นหนี้สินและออกเพียงใบเสร็จ) ซึ่งอธิบายไว้ในข้อ 2.4

## 4. สิ่งที่กระทบการออกแบบระบบโดยตรง

**หนึ่ง — ราคาบนหน้าจอเป็นเรื่องของกฎหมาย** [ตัวบท ม.86/6 วรรคแรก] สนามที่จด VAT และใช้สิทธิค้าปลีกต้องแสดงราคารวม VAT แล้ว ⇒ `PriceBand` ที่เก็บ 300 บาท/ชม. ต้องมีคำตอบว่าเลขนั้นรวม VAT หรือไม่ และคำตอบต่างกันตามสถานะ VAT ของสนาม ณ วันนั้น · ในทางกลับกัน **สนามที่ไม่จด VAT ต้องไม่มีข้อความ "รวม VAT แล้ว" บนหน้าจอ** [ตีความ]

**สอง — สถานะ VAT ต้องมีวันที่เริ่มมีผล** [ตีความ] สนามข้ามเส้น 1.8 ล้านกลางปีได้ และเอกสารย้อนหลังต้องถูกพิมพ์ด้วยกฎของยุคที่มันเกิด ⇒ เป็นเวอร์ชันแบบเดียวกับ `PriceList`/`CancellationPolicy` ไม่ใช่ boolean

**สาม — ชนิดเอกสารต้องแยกที่ระดับข้อมูล ไม่ใช่ระดับ template** [ตีความจากโทษตามมาตรา 86/13 + 90/4(3)] สนามที่ไม่จด VAT ต้องไม่มีเส้นทางใดในระบบที่ผลิตเอกสารซึ่งมีคำว่า "ใบกำกับภาษี" หรือบรรทัด VAT ได้

**สี่ — มัดจำ = สองเอกสารต่อการจอง** [ตัวบท ป.73/2541 + ม.105 วรรคจ่ายเป็นงวด] ทุกก้อนเงินที่รับต้องมีเอกสารของตัวเอง ⇒ ตรงกับที่ระบบเขียน `PaymentReceipt` ต่อก้อนเงินอยู่แล้ว แต่ **เอกสารภาษีต้องผูกกับ receipt ไม่ใช่กับ booking**

**ห้า — เลข running แยกต่อสนาม** [ตีความ] ตามทางที่เลือก (สนามออกเอง แพลตฟอร์มเป็นระบบ) · ถ้าวันหนึ่งเปลี่ยนไปใช้กลไกตัวแทนจริง เลขต้องกลายเป็นชุดกลางของแพลตฟอร์มและเอกสารต้องแสดงเลขผู้เสียภาษีสองชุด — **เป็นการเปลี่ยนโครง ไม่ใช่การเปลี่ยน config**

**หก — ยกเลิกการจอง = ใบลดหนี้ ภายในเดือนภาษีที่เหตุเกิด** [ตัวบท ม.86/10 + ประกาศฯ 82] ⇒ ต้องมีงานที่ปิดให้เสร็จภายในเดือนปฏิทิน และการข้ามเดือนเป็นข้อยกเว้นที่ต้องมี "เหตุจำเป็น" ไม่ใช่ทางปกติ · เกินสองเดือนไม่มีทางในตัวบทเลย

**เจ็ด — เอกสารแก้ไม่ได้และลบไม่ได้โดยปริยาย** [ตีความจากโครงของตัวบท] ทุกกลไกที่กฎหมายให้ไว้ (ใบเพิ่มหนี้ ใบลดหนี้ ฉบับใหม่แทนฉบับที่ยกเลิก ใบแทน) เป็นการ **เขียนเพิ่ม** ที่อ้างเลขที่ฉบับเดิม ⇒ ตรงกับสถาปัตยกรรม append-only ที่ repo ใช้อยู่แล้ว

**แปด — รายงานภาษีขายเป็นรายเดือนภาษีต่อสถานประกอบการ และต้องรองรับยอดลบ** [ตัวบท แบบแนบท้าย + ม.87] ⇒ export แยกตามสถานประกอบการ · ใบลดหนี้เป็นแถวใหม่ที่มียอดลบ ไม่ใช่การลบแถวเดิม · และต้องมี timestamp ที่ลงรายการเพื่อพิสูจน์กฎสามวันทำการ

**เก้า — การหักภาษี ณ ที่จ่ายของลูกค้านิติบุคคลทำให้ "ยอดสลิป = ยอด QR" เป็นเท็จ** [ตีความ] สลิปจะมายอดขาด 3–5% และสนามต้องได้รับหนังสือรับรองการหักภาษี ณ ที่จ่ายคู่กัน ⇒ นี่เป็นการตัดสินใจเชิงผลิตภัณฑ์

**สิบ — retention เจ็ดปีนับจากวันยื่นแบบ และต้องพิมพ์ได้ที่สถานประกอบการ** [ตีความจาก ม.87/3 + พ.ร.บ.การบัญชี ม.14]

## 5. ผลต่อโค้ด CourtPaka โดยเฉพาะ (ข้ออนุมานจากงานวิจัย ไม่ใช่ข้อค้นพบทางกฎหมาย)

ส่วนนี้แยกออกจากข้อค้นพบทางกฎหมายโดยเจตนา ทุกบรรทัดเป็น **[ตีความ]** ที่ผู้วิจัยลากมาจากข้อ 2 และควรถูกตรวจซ้ำหลังนักบัญชีตอบ Q1

- **`Venue.Business` ต้องเปลี่ยนจากสถานะ VAT แบบค่าเดียวเป็นค่าที่มีวันที่เริ่มมีผล** และเอกสารต้อง snapshot สถานะนั้น ณ วันรับเงิน ไม่ใช่อ่านค่าปัจจุบัน — เหตุผลเดียวกับ BR-05 ที่การจอง snapshot ราคาและนโยบายยกเลิก
- **ต้องเพิ่ม "ประเภทผู้เสียภาษีของสนาม" (บุคคลธรรมดา / นิติบุคคล)** ลงใน `Venue.Business` เพราะมันตัดสินว่าสนามมีหน้าที่หักภาษี ณ ที่จ่ายจากค่าคอมมิชชันหรือไม่ และห้ามเดาจากรูปแบบเลขผู้เสียภาษี
- **เลขเอกสารต้องเป็น running number ต่อสนาม ต่อชนิด ต่อปี** (ตรงกับรูปแบบใน PRD 7.4) แยกจาก GUID ภายใน · แต่ **S-24 ที่เขียนว่า "เรียงต่อเนื่องไม่ข้าม" ยังไม่มีตัวบทรองรับ** ⇒ ก่อนสร้างกลไกกันเลขขาดที่แพง ควรยืนยันว่ากฎหมายบังคับจริง
- **เอกสารภาษีต้องผูกกับ `PaymentReceipt` ไม่ใช่กับ `Booking`** เพราะ tax point อยู่ที่การรับเงิน ⇒ การจองที่วางมัดจำแล้วจ่ายส่วนที่เหลือหน้าเคาน์เตอร์ (US-26/US-28) จะมีเอกสารสองใบโดยธรรมชาติ ไม่ใช่กรณีพิเศษ
- **ยอดในใบลดหนี้ต้องมาจาก `Refunds.DueFor(...)` ตัวเดียวกับที่ระบบใช้อยู่** ไม่ใช่จากราคาเต็ม — และกฎ "ส่วนตามนโยบายเป็นส่วนของราคา ไม่ใช่ของเงินที่จ่ายมา" ที่ CLAUDE.md บันทึกไว้แล้ว สอดคล้องกับ "มูลค่าที่ถูกต้อง" ที่มาตรา 86/9–86/10 ต้องการ
- **สนามที่ `VatRegistered = false` ต้องไม่มี code path ที่ผลิตเอกสารมี VAT ได้** ทางที่ตรงกับสถาปัตยกรรมนี้คือแยกชนิดเอกสารเป็นชนิดข้อมูลต่างกัน (ใบกำกับภาษีอย่างย่อ / เต็มรูป / ใบเสร็จรับเงิน) แล้วให้ตัวตัดสินอยู่ที่เดียวแบบเดียวกับ `BookingEligibility.MissingFor(...)` และ `VenueDecisions`
- **`SalesTaxReportLine` เป็นตารางใหม่แบบ append-only มี trigger** ตามแนวที่ repo ใช้กับตาราง history ทุกตัว โดยมีอย่างน้อย: เดือนภาษี · สถานประกอบการ (สำนักงานใหญ่/สาขา) · วันที่เอกสาร · เล่มที่/เลขที่ · ชื่อผู้ซื้อ · เลขผู้เสียภาษีผู้ซื้อ (nullable) · สาขาของผู้ซื้อ (nullable) · มูลค่าก่อน VAT · VAT · ชนิดเอกสาร · `RecordedAt` (พิสูจน์สามวันทำการ) · `SourceBookingId` — และต้องเพิ่มชื่อตารางใน `AuditTrailTests`
- **export รายงานภาษีขายต้องมี BOM และหัวคอลัมน์ภาษาไทยตรงตามแบบแนบท้าย** ซึ่งเป็นกฎเดียวกับที่ US-16 ใช้อยู่แล้วใน `core/venues/revenue-csv.ts` — และเพราะหัวตารางเป็นภาษาคน จึงต้องประกอบที่ฝั่ง browser ตามกฎ US-23 เหมือนเดิม
- **ต้องล็อกเดือนภาษีหลังยื่น ภ.พ.30** (period close) ไม่งั้นรายงานที่ export จะไม่ reconcile กับที่ยื่นไปแล้ว
- **US-21 ต้องมีสถานะ "ค้างชำระ/เกินกำหนด" ของใบแจ้งหนี้ค่าคอมมิชชัน** เพราะ netting ทำไม่ได้ในโมเดลปัจจุบัน และแพลตฟอร์มแบกความเสี่ยงหนี้สูญ · ต้องมีที่เก็บ **สำเนา 50 ทวิ ที่สนามส่งกลับมา** เพราะเป็นเครดิตภาษีของแพลตฟอร์มเอง · และ **"ออกบิล 100 แต่รับเงิน 97" ต้องไม่ถูกอ่านว่าหนี้ค้าง 3** — เป็นบั๊กตระกูลเดียวกับ `takeMoney` vs `toPayBaht > 0` ที่เคยเจอ
- **ข้อมูลผู้ออกเอกสารของแพลตฟอร์มควรเป็น config ของ deployment** เหมือน `App:PlatformAdmins` ไม่ใช่คอลัมน์ เพราะมันเปลี่ยนเมื่อรูปนิติบุคคลหรือสถานะ VAT ของแพลตฟอร์มเปลี่ยน
- **วันที่ 23 (deadline e-Filing) ต้องเป็น config** เพราะมาตรการขยาย 8 วันมีวันหมดอายุ
- **ฟีเจอร์ที่มีมูลค่าจริงและระบบทำได้อยู่แล้ว: เตือนสนามเมื่อยอดสะสมปีนี้ใกล้ 1.8 ล้าน** — `Takings` และ dashboard US-15 มีข้อมูลนี้ครบ และการพลาดเกณฑ์นี้คือความเสี่ยงที่แพงที่สุดของสนาม
- **ต้องมี DPA ในข้อตกลงสนาม** (`App:VenueAgreementVersion`) ตาม PDPA มาตรา 40 วรรคสาม · และการ "ออกเอกสารให้อัตโนมัติ" ต้องมีร่องรอยว่าสนามเป็นผู้สั่งไว้ล่วงหน้า ไม่ใช่แพลตฟอร์มตัดสินเอง — แนวเดียวกับ `UserConsent` ที่เก็บเป็นแถวใหม่ทุกครั้ง
- **privacy notice ต้องบอกว่าเอกสารภาษีเก็บตามกฎหมายและไม่ลบตามคำขอ** เพราะใบกำกับภาษีเต็มรูปที่มีชื่อ-ที่อยู่ผู้ซื้อ anonymise ไม่ได้ ⇒ ต่อยอดจากกฎที่มีอยู่แล้วว่า "ที่ที่แสดงอีเมลผู้จองต้องคืน null เมื่อ `DeletedAt` ไม่ว่าง"
- **หน้าจอจองควรมีข้อความขอเลขผู้เสียภาษีสำหรับผู้ที่ต้องการใบกำกับภาษีเต็มรูป** เพราะคำชี้แจงกรมสรรพากรให้ผลเป็น safe harbour แก่สนาม — และควรถามตอนจอง ไม่ใช่ตอนขอเอกสารภายหลัง เพื่อหนีปัญหา "เรียกคืนฉบับเดิม" ของ PDF

## สรุป

งานวิจัยรอบนี้เปลี่ยนรูปของ Q1 จาก "ต้องออกเอกสารอะไร" ไปเป็น "**ใครเป็นผู้ออก และเอกสารผูกกับอะไร**" ซึ่งเป็นคำถามที่ลึกกว่าและตอบยากกว่า สองคำตอบที่ตัวบทให้ชัดคือ tax point อยู่ที่ **การรับเงิน** (ไม่ใช่วันเล่น ไม่ใช่วันยืนยันการจอง) และการยกเลิกเดินทาง **ใบลดหนี้** (ไม่ใช่การยกเลิกเอกสาร) — สองข้อนี้รวมกันแปลว่าระบบเอกสารภาษีต้องผูกกับ `PaymentReceipt` และเดินแบบ append-only ซึ่งเป็นสถาปัตยกรรมที่ repo นี้มีอยู่แล้วทุกชิ้น ⇒ **US-07 และ US-16 ไม่ต้องรื้ออะไร แต่ต้องเลิกใช้ booking เป็นหน่วยของเอกสาร**

สิ่งที่ยังบล็อกอยู่จริงมีสองชั้น และสำคัญไม่เท่ากัน ชั้นที่ **บล็อก US-07/US-16 โดยตรง** คือคำถามว่าคอร์ทรายชั่วโมงเป็นค่าเช่าหรือค่าบริการ เพราะถ้าเป็นค่าเช่าที่ยกเว้น VAT ตามมาตรา 81 ทั้งหัวข้อใบกำกับภาษีในรายงานนี้ก็ไม่มีผลกับสนามส่วนใหญ่เลย — **คำถามนี้ควรเป็นคำถามแรกที่ถามนักบัญชี ไม่ใช่คำถามที่แปดในรายการ** และรอบวิจัยถัดไปควรเริ่มจากการอ่านข้อหารือสนามกอล์ฟสามฉบับที่ยังไม่ได้เปิด ส่วนชั้นที่ **บล็อก US-21** คือการเลือกรูปนิติบุคคลของแพลตฟอร์มและชื่อรายการในสัญญา ซึ่งเป็นการตัดสินใจทางธุรกิจที่ตัวบทตอบให้ไม่ได้ แต่ตัวบทบอกผลของแต่ละทางไว้ชัดพอจะตัดสินได้แล้ว — เพดานหักค่าใช้จ่าย 100,000 บาทของมาตรา 40(2) ตอบคำถาม "บุคคลธรรมดาหรือบริษัท" ให้เกือบเสร็จโดยไม่ต้องรอใคร

ข้อสุดท้ายที่ควรพูดตรง ๆ กับนักบัญชี: รายงานนี้พบ **ช่องว่างเชิงโครงสร้างที่ไม่มีคำตอบเผยแพร่** อยู่ข้อหนึ่ง — แพลตฟอร์มที่ไม่ได้รับเงินแทนสนามไม่เข้าเส้นทางตัวแทนใดเลยในประมวลรัษฎากร ทางที่เหลือคือ "สนามออกเอง แพลตฟอร์มเป็นโรงพิมพ์" ซึ่งเป็นทางที่ปลอดภัยที่สุด แต่**ปลอดภัยเพราะไม่มีใครบอกว่าผิด ไม่ใช่เพราะมีใครบอกว่าถูก** ความต่างนั้นสำคัญพอที่จะยื่นข้อหารือก่อนลงมือ ไม่ใช่หลัง
